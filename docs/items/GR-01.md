# GR-01: deterministic quote grounding

Status and dependencies live in the canonical backlog, not duplicated here.

- Target references: ARCHITECTURE.md Assess ("Deterministic checks: every quote appears verbatim in
  its chunk"; "quotes must match verbatim"); D-003 (neutral invented fixtures only).
- Objective: new pure module `core/grounding.py`, a port of the quote-location checks from the
  operator's repository TKontu/raappa, file `src/services/extraction/grounding.py` at commit
  6c73d9f690564230c5088b9c9c5e35dd980d2d16. That repository has no licence file; it has the same
  owner as this one. Provides `GroundingResult`, `ground_and_locate(quote, content)`,
  `precompute_content_maps(content)` + `ground_and_locate_precomputed(...)`,
  `verify_quote_in_source(quote, source_content) -> float` and `is_negation_quote`, with the tiered
  locators and their normalisation helpers (whitespace/case, punctuation strip, markdown strip,
  position maps, word-window similarity). Behaviour is ported as-is; the only restructuring is that
  the plain and precomputed entry points share one tier runner (`_locate`).
- Dropped from the source (not needed by the ported core): `GROUNDING_DEFAULTS`, `_METADATA_KEYS`,
  `verify_numeric_in_quote`, `verify_string_in_quote`, `verify_list_items_in_quote`,
  `_coerce_quote`, `score_field`, `compute_grounding_scores`,
  `compute_entity_list_grounding_scores`, `extract_field_types_from_schema`,
  `extract_entity_list_groups`, `_to_number`, `_extract_numbers_from_text`,
  `_parse_number_string`, `_numbers_match`, `ground_field_item`, `ground_entity_item`,
  `ground_entity_fields`, `score_entity_confidence`, `compute_chunk_grounding`,
  `compute_chunk_grounding_entities`, `compute_source_grounding_scores`.
- Scope / non-goals: no I/O, no LLM, no new dependency. Not wired into an extractor; the assessment
  schema is unchanged. Connections: unwired by design. The production caller will be the Phase 1
  Assess row (extractor checks).
- Acceptance: `tests/test_grounding.py` was written first and failed with `ModuleNotFoundError`. It
  covers each tier, checks that spans map back to the original content
  (`content[start:end] == matched_span`), and covers no-match, empty/None quotes, negation detection,
  and precomputed-path equals plain-path. `uv run mypy core` passes under strict mode.
- Evidence / residuals:
  - Source commit: TKontu/raappa@6c73d9f690564230c5088b9c9c5e35dd980d2d16 (no licence file, same
    owner).
  - Scale: tiers 1–4 are linear in content length, though each call does several passes. The
    precomputed maps only cover tiers 1–2. Tier 2 rebuilds the punctuation map and tier 3 rebuilds the
    markdown, normalised and punctuation maps on every call, so one chunk serving many quotes still
    pays O(len(content)) per quote for misses past tier 1. `verify_quote_in_source`'s word window
    is super-linear: it recounts in O(n) whenever a quote word enters or leaves the window, so the
    worst case is O(N·n) for N content words and an n-word quote.
  - Behaviour carried over from the source unchanged: tier 2 often catches inline markdown (`**`,
    `[`) before tier 3 does. Tier 4 does not strip punctuation, so words with punctuation attached
    lower the overlap. For tier 4, `matched_span` is the matched line, or the first 200 characters
    of the matched block.

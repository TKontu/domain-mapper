# SD-01: per-URL snapshot diff of one entity across two crawl runs

Status and dependencies live in the canonical backlog, not duplicated here.

- Target references: ARCHITECTURE.md §4 Crawl & snapshot ("Re-crawl": only changed snapshots
  (hash) trigger re-assessment); D-003 (neutral wording).
- Objective: read-only `core.snapshot_diff.diff_entity_runs(engine, entity_id, base_run_id=None,
  head_run_id=None)` and `landscape snapshot-diff --entity ID [--base-run R] [--head-run R]`
  classify each URL of one entity as changed / unchanged / added / removed by comparing the
  latest snapshot `sha256` per URL in two runs (default: the two most recent runs holding
  snapshots for the entity).
- Scope / non-goals: core module, CLI subcommand, offline SQLite tests. No re-assessment trigger,
  no schema change, no writes, no body diff, no live crawl.
- Acceptance: `tests/test_snapshot_diff.py` and `tests/test_cli_snapshot_diff.py` cover the four
  statuses, latest-per-URL within a run, default and explicit run selection, too-few-runs and
  named-run-without-snapshots errors (exit 2), other entities ignored, DB error convention; gate
  green.
- Evidence / residuals: PR (assignment 198/A1). Residuals: not yet run against a real crawl
  database; selective re-assessment consuming the diff is a later SD row.

# DS-02: `landscape web-search --save` persists results as `candidate` rows

Status and dependencies live in the canonical backlog, not duplicated here.

- Target references: ARCHITECTURE.md §1 Discover (output `candidate(name, url, country_hint, segment_hint, channel, query, found_at)`) and §5 data model (`candidate(id, name, url, country_hint, segment_hint, source_id, query, found_at, resolved_entity_id)`); D-003 (no private scope words; search instance URL never in tracked files or output; tests use `http://search.invalid`); D-004. Builds on DS-01, AD-12 (`adapters/searxng.py`), AD-02 (`core/source_catalogue.py`).
- Objective: `uv run landscape web-search --scope <dir> --query "<q>" --save` writes each result as one `candidate` row (`channel="search"`, the query text, aware-UTC `found_at`, rank order) and prints `saved N candidates` after the result lines. Without `--save` behaviour is unchanged and no engine is created.
- Scope: new `core/candidate_store.py` (`Candidate` on `core.runs.Base`, `NewCandidate`, `record_candidates(engine, rows) -> int`, one transaction, batched flushes), `--save` in `core/cli.py` `web_search`, tests. Columns: `name` = result title; `country_hint`, `segment_hint`, `source_id` (no FK yet), `resolved_entity_id` (indexed, no FK) NULL. Non-goals: query generation, entity resolution, migrations, other channels, live Postgres.
- Acceptance: offline tests (`tests/test_candidate_store.py`, `tests/test_cli_web_search.py`) cover one row per result with channel/query/aware-UTC found_at in rank order; `saved N candidates`; zero results → `saved 0 candidates`, exit 0; DB failure → `error: database unavailable (<ExcType>)` on stderr, exit 2, no database URL; SearchError with `--save` writes nothing; no engine without `--save`; blank url/channel → ValueError before a session (nothing written); empty input → 0, nothing written.
- Connections / scale: production caller `web_search --save`; consumer is the future Phase 1 Resolve row (unwired by design). Results are bounded by `--limit` ≤ 100, so the one transaction is bounded.
- Residuals: no dedup (each search is a distinct observation); no migrations (`create_all`); no `source_id` link to the `source` catalogue; Postgres unexercised; live `--save` not run.
- Outcome (round 30): merged PR #76 at head 1cc52e8; offline gate seen on main c23cafa. Review note: `web_search` catches `Exception` broadly, so a `ValueError` from a blank result url would print as `database unavailable (ValueError)`.
- Seen (round 31): live `--save` on main b86219c stored 5 candidate rows (channel `search`, query recorded), exit 0. The blank-url note above cannot occur through `SearxngSearch`, which drops results without an http(s) url.

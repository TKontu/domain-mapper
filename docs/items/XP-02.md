# XP-02: formula-injection escaping in scores-export CSV

Status and dependencies live in the canonical backlog, not duplicated here.

- Origin: XP-01 residual. Text cells (segment and layer ids, rubric_version) come from scope packs
  and could open as formulas in a spreadsheet. No design change.
- Objective: in `landscape scores-export --format csv`, a text cell (any value that is not an
  int, float or bool, including a `;`-joined list) whose first character is one of `=`, `+`, `-`,
  `@`, TAB or CR is written with a leading `'`. Numeric and boolean values are written unchanged
  (so `-0.5` stays `-0.5`); empty cells stay empty. JSON Lines output is unchanged.
- Acceptance: tests show (a) a segment id `=cmd` → cell `'=cmd`, and each of `+ - @ \t \r` as the
  first character is prefixed; (b) a joined list `a;=b` is not prefixed (first char `a`) while
  `=a;b` is; (c) a negative float score stays unprefixed; (d) `--format jsonl` output for the same
  data is byte-identical to before; (e) existing tests pass. Full local gate green.
- Residuals: escaping is the common OWASP prefix rule; a consumer that strips the `'` sees the raw
  text. Not seen over real assessments.

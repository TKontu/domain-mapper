# LB-02: per-backend LLM cost rates from settings

Status and dependencies live in the canonical backlog (`todo.md`, Phase 1 › Screen).

- Target references: ARCHITECTURE.md §6 model routing ("Per-run budgets for cloud tokens; every call logged in `llm_call`"); LB-01 residual (`build_llm` passed cost rates 0); D-003.
- Objective: per-backend token cost rates come from settings, so `llm_call.cost` and the LB-01 cap are effective once the operator sets rates.
- Design: `Settings` gains `local_cost_per_mtok_in/out` and `cloud_cost_per_mtok_in/out` (USD per million tokens, default 0.0; env `DM_LOCAL_COST_PER_MTOK_IN/OUT`, `DM_CLOUD_COST_PER_MTOK_IN/OUT`; negative or non-finite → ValueError naming the variable). `_build_inner` passes the local pair to `OpenAICompatibleLLM`, the cloud pair to `AnthropicLLM`. Rates are operator configuration; no provider prices are hardcoded.
- Connections / scale: production caller `landscape screen` via `_make_screen_llm` → `build_llm`; O(1).

# MG-01: merge guard refuses without a passing local-gate result at the reviewed head

Status and dependencies live in the canonical backlog (`todo.md`, Phase 0 › Repo & infra).

- Target references: AGENTS.md "Merging (D-002)" and "Local gate first"; D-002; operator ruling
  2026-11-28 (dashboard item merge-guard-ci) and its correction: LOCAL TESTS DECIDE. The minimal CI
  (`.github/workflows/check.yml`) is unchanged and only a backstop.
- Objective: `scripts/merge_guard.py PR --head SHA` refuses unless (1) the round ledger
  (`.agent-runs/<round>/round.json` and the `results/*.json` files it lists, written by
  `scripts/round.py` and read with its `read`/`inside` helpers) holds a result whose `head_sha`
  equals the reviewed head exactly, whose every check has status `passed`, and whose checks
  together cover pytest, `ruff check`, `ruff format --check` and mypy (matched on command text;
  each missing component is named in the refusal); and (2) no CI check on the PR head concluded
  failed (CheckRun FAILURE, ERROR, CANCELLED, TIMED_OUT, ACTION_REQUIRED; StatusContext
  FAILURE/ERROR). Pending, in-progress or absent CI does not block. Existing refusals stay.
- Rule for several results at the head: one passing, complete result suffices; non-passing results
  at the same head are then ignored. Results at other heads never count.
- Scope / non-goals: scripts/merge_guard.py, tests/test_merge_guard.py, this file, the todo.md
  row. No .github/ or CI changes, no scripts/round.py behaviour change, no AGENTS.md edit.
- Acceptance: tests/test_merge_guard.py shows refusal for no result at head, a result at another
  head, a failed/unavailable/waived check, a missing gate component, and a failed CI check
  (CheckRun and StatusContext); acceptance for a complete passing result with CI green, pending or
  absent. Gate `uv run pytest -q && uv run ruff check . && uv run ruff format --check . && uv run
  mypy core app` green offline.

# FE-02: per-entity static pages linked from mosaic

Status and dependencies live in the canonical backlog, not duplicated here.

- Target references: ARCHITECTURE.md frontend row (static site, host anywhere, no backend); D-003
  (neutral fixtures only, `scopes/_example`); GV-01/GV-02/GV-03 (CLI composition root in `app/`,
  core imports no adapters); round 106 decision (Python-rendered static HTML, no JS toolchain).
  Builds on FE-01.
- Objective: `landscape mosaic ... --out PAGE.html --entity-dir DIR` (optional) additionally
  writes one self-contained HTML page per scored entity at `DIR/<safe-entity-id>.html`: entity id
  heading, per-topic score/coverage, then every rubric criterion in rubric order with status
  label/colour from `status_scale`, confidence, rationale and each evidence quote with url link and
  fetched_at ("not assessed" row when none). Mosaic row headers link to the entity page; each
  entity page links back. Without the flag the mosaic is byte-identical to FE-01.
- Scope / non-goals: `app/mosaic.py::render_entity_page(pack, scores_line, cells_for_entity,
  mosaic_href) -> str` (pure), `entity_slug` (`[A-Za-z0-9_-]`, max 64 chars, plus 8-hex sha256
  suffix), optional `entity_href` on `render_mosaic`; `app/cli.py::run_mosaic` creates DIR and
  writes each file via `.tmp` + rename. Non-goals: JS, CDN assets, maps, network, DB,
  export/scores-export shape changes, profile weights, layer/segment filtering.
- Acceptance: offline pytest (`tests/test_entity_page.py`) failing at base, passing at head: one
  page per scored entity with every criterion in rubric order and label/colour, quote, url,
  fetched_at; mosaic links `<dir-relative>/<slug>.html` and pages link back; ids with `/`, `..`,
  spaces or `<` give safe filenames inside DIR and escaped text; no-flag output equals base output
  (sha256 pinned); atomic writes; exit 2 on missing inputs or bad scope; no `http(s)://` refs
  except evidence links. Full gate green, both ratchets pass.
- Evidence / residuals: round 107/A1 PR (see todo.md); no browser run (seen offline only); with
  `--entity-dir` the scores and export lines are held in memory, O(entities x criteria); entity
  pages written before the mosaic, so a failure mid-run can leave some pages without a mosaic;
  stale pages for entities no longer scored are not removed.

# AD-08: `FetchResult.fetched_at` time-zone policy

Status and dependencies live in the canonical backlog (`todo.md`, Phase 0 › Adapters, AD-06 row
residual "`fetched_at` default is naive local time (set a tz policy then)").

- Target references: ARCHITECTURE.md §4 (`FetchResult` fields: `final_url, status, content_type,
  body_bytes, headers, fetched_at`); existing aware-UTC convention in `core/runs.py` and
  `core/llm_calls.py` (`_utcnow()` → `datetime.now(UTC)`); D-003 (no domain words).
- Objective: `FetchResult.fetched_at` defaults to an aware UTC datetime, and an explicitly passed
  naive `fetched_at` raises `FetchError`; an aware non-UTC value is accepted and kept as given.
- Semantics: the default factory is `datetime.now(UTC)` (`utcoffset()` 0). `__post_init__` rejects
  a `fetched_at` whose `tzinfo` is `None` or whose `utcoffset()` is `None` (naive-like tzinfo), and
  does not convert or rewrite a tz-aware value. The check runs before the headers copy; the record
  stays frozen.
- Scope / non-goals: `adapters/fetcher.py` (default, `__post_init__` check, docstring), its tests
  (`tests/test_fetcher_adapter.py`), this file. Non-goals: other adapters, a real fetcher,
  storage/DB columns (the `snapshot` table's `fetched_at` column policy is not changed here).
- Acceptance: `uv run pytest tests/test_fetcher_adapter.py` — tests written first, failing at base
  `40dcf96` with `assert None is not None` for the default's `tzinfo` and
  `DID NOT RAISE FetchError` for a naive explicit value. They now show (a) the default's `tzinfo`
  is not `None` and `utcoffset()` is 0; (b) a naive explicit value raises `FetchError`; (c) an aware
  `UTC+02:00` value is returned unchanged (same object, offset +2h). Negative controls: reverting the
  default to `datetime.now` fails (a); deleting the `__post_init__` guard fails (b).
- Connections / scale: **unwired by design**, like AD-06; first production caller is the Phase 1
  Crawl & snapshot row. Scale: a constant-time check per result; N/A.

# AS-08: Reranker over the retrieved candidate pool

Status and dependencies live in the canonical backlog, not duplicated here.

- Target references: ARCHITECTURE.md §4 stage 7 (hybrid retrieval → top-k → **reranker** → top-n);
  `core/retrieve.py` (`retrieve_evidence`); `adapters/embedding.py` (`Reranker`, `RerankHit`,
  `HttpReranker`); D-003 (neutral fixtures only).
- Objective: `retrieve_evidence` gains keyword-only `reranker: Reranker | None = None`. With a
  reranker the candidate pool — keyword top-`k`, or the fused top-`k` on the hybrid path — has its
  texts loaded once and is reranked with `reranker.rerank(criterion.question, texts, top_n=n)`. The
  result is returned in reranker order (score descending, ties by chunk id ascending) as
  `(chunk_id, text)`, cut to `n`; an out-of-range hit index raises `ValueError`. `reranker=None`
  leaves both the AS-02 keyword-only and AS-06 hybrid paths byte-for-byte unchanged.
- Scope / non-goals: `core/retrieve.py`, `tests/test_retrieve.py`, this file, its `todo.md` row. No
  `core/cli.py` (lane 65/A1 owns it), no live rerank calls, no change to `adapters/embedding.py`.
- Connections / scale: `retrieve_evidence` is called by `landscape assess` (`core/cli.py`); that
  caller does not pass `reranker` yet. The argument is **unwired by design** until AS-09 builds an
  `HttpReranker` with `build_reranker(settings, model)` and passes it. Scale: one rerank call over
  at most `k` texts per query; the candidate texts are loaded in one query. The `search_chunks`
  O(entity corpus) scan is inherited (AS-02/AS-06 residual).
- Acceptance: offline pytest (SQLite fixtures, fake `Reranker`) failing at base and passing at head:
  the reranker reorders both the keyword and hybrid pools, receives the criterion question and at
  most `k` texts, cuts to `n`, orders by score with ties by chunk id ascending, and an out-of-range
  hit index raises `ValueError`; the `reranker=None` tests are unchanged. Full gate green.
- Evidence / residuals: PR #153 for assignment 65/A2 (base b4cb0c9), with the revision-bound head
  and gate output in the PR body. At base with the new tests:
  `uv run pytest tests/test_retrieve.py -q` → 6 failed, 14 passed, all six
  `TypeError: retrieve_evidence() got an unexpected keyword argument 'reranker'`. At head the
  targeted suite gives 20 passed and the full offline gate 1231 passed, 5 skipped (PostgreSQL paths,
  `DM_TEST_DATABASE_URL` unset), 158 subtests passed. Residuals: `reranker` is unwired until AS-09;
  no live rerank call has run (offline fake `Reranker` only); an empty candidate pool still calls
  `rerank` with no documents, which `HttpReranker` short-circuits without a request.

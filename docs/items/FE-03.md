# FE-03: mosaic --segment filter

Status and dependencies live in the canonical backlog, not duplicated here.

- Target references: ARCHITECTURE.md frontend row (static site, no backend); D-003 (neutral
  fixtures only, `scopes/_example`); GV-01/GV-02/GV-03 ratchets; round 106 decision
  (Python-rendered static HTML, no JS toolchain); M1 "one layer of one scope". Builds on FE-01/FE-02.
- Objective: `landscape mosaic ... --segment ID` (optional, repeatable) renders only scores lines
  whose `segments` list contains one of the given ids (union, input order); with `--entity-dir`,
  entity pages are written only for kept entities. The page heading names the active filter by
  segment label (escaped). An id not in the scope pack's `segments` exits 2 naming it and writes
  nothing. Without the flag, mosaic and entity-page output is byte-identical to FE-02.
- Scope / non-goals: `app/mosaic.py::filter_by_segments(scores_lines, segment_ids)` (pure,
  streaming) and optional `heading` on `render_mosaic`; `app/cli.py::run_mosaic`/`mosaic` wiring.
  Non-goals: layer filtering (scores lines carry no layer), JS, maps, network, DB,
  export/scores-export shape changes, profile weights.
- Acceptance: offline pytest (`tests/test_mosaic_filter.py`) failing at base, passing at head:
  filter keeps matching entities in input order and repeated flags union; entity pages only for
  kept entities; unknown id exits 2 with id in message, no files written; no-flag output equals
  pre-change output; heading shows label, escaped. Full gate green, both ratchets pass.
- Evidence / residuals: round 108/A1 PR (see todo.md); no layer filter (scores lines carry no
  layer); no browser run (seen offline only); export lines are not filtered (cells for dropped
  entities are folded into the dict but never rendered).

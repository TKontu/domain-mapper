# XP-04: CSV format for export

Status and dependencies live in the canonical backlog, not duplicated here.

- Origin: XP-01..03 gave `scores-export` and `attributes-export` a CSV format; `landscape export`
  (AS-12/AG-06, `run_export`) still only accepted `--format json`. Additive output format; no
  decision needed.
- Objective: `landscape export --scope S --format csv --out PATH` writes one RFC 4180 CSV row per
  current assessment; `--format json` output is byte-identical to before.
- Acceptance: (a) header always written (also for an empty view): `id, entity_id, criterion_id,
  status, confidence, rationale, rubric_version, extractor_model, verifier_model, decided_by,
  route_kind, run_id, created_at, evidence_count, grounded_count, first_url, first_fetched_at`
  (first_* from the first evidence row, empty when none or null). (b) one row per current
  assessment in JSON order; `--entity/--criterion/--rubric-version` apply identically. (c) every
  cell via `_csv_cell` (XP-02 formula escaping, numbers unchanged, None empty); timestamps as
  isoformat. (d) unknown `--format` exits 2 before setup or any write, naming `json, csv`;
  tmp-then-rename atomicity; rows streamed. (e) summary line unchanged. (f) JSON byte-identical.
  (g) gate green.
- Non-goals: Parquet, other export commands, JSON changes, per-quote rows.
- Residuals: Parquet not done; not seen over real data; PostgreSQL unexercised.

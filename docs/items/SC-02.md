# SC-02: `landscape screen` CLI over unscreened entities

Status and dependencies live in the canonical backlog (`todo.md`, Phase 1 › Screen).

- Target references: ARCHITECTURE.md §4 stage 3 (Screen & classify), §5, §6 model routing; SC-01 (`screen_entity`); AD-01 (`build_llm`); D-003.
- Objective: `landscape screen --scope S [--limit N] [--dry-run]` screens each `unscreened` entity of the scope from its stored chunk text (chunk → snapshot.entity_id, snapshot id then seq, read stops at 8000 chars) with the local small model, writes one `screen_result` row and moves the entity status to `in_scope`, `out_of_scope` or `borderline`, one transaction per entity.
- Policy (SC-01 residual settled by the planner, round 45): invalid model output (`ScreenError`, including an unknown segment id) or `LlmError` prints `error <id> <Class>: <msg>`, leaves the entity `unscreened` for a retry and makes the run exit 1; an entity with no chunk text prints `skipped <id> no-text`. Final line `screened S skipped K errors E`; exit 2 on bad setup.
- Scope: `core/cli.py`, `core/entity_store.py` (`iter_entities(status=)`, `EntityRef.name`), new `core/screen_store.py`, tests `tests/test_screen_cli.py`, `tests/test_screen_store.py`.
- Connections / scale: production caller of `screen_entity`, `build_llm` and `record_screen_result`/`load_entity_text`; `screen_result` consumers (review queue, Assess) are later rows. Entities keyset-paged; one LLM call per entity, sequential.

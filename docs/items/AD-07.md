# AD-07: `Parser` adapter interface

Status and dependencies live in the canonical backlog (`todo.md`, Phase 0 › Adapters).

- Target references: ARCHITECTURE.md §4 (Parse & chunk: HTML → clean Markdown keeping
  headings; PDF / scanned brochures / terms → MinerU → Markdown with page numbers, tables
  preserved), §10 (genericity contract); D-003 (no domain words); `adapters/search.py`
  (Protocol + frozen-dataclass house style).
- Objective: `adapters/parser.py` defines a `runtime_checkable` `Parser` protocol with one
  method `parse(body: bytes, *, content_type: str, url: str) -> ParsedDocument`; frozen
  `ParsedDocument(markdown, pages, title, parser)` and frozen `ParsedPage(number, markdown)`;
  `ParseError` (a `ValueError`); and `InMemoryParser`, a fake returning canned documents keyed
  by content type.
- Semantics: content-type matching ignores parameters and case (`text/html; charset=utf-8`
  finds `text/html`); a missing, blank or unsupported content type raises `ParseError`. `pages`
  is empty for HTML and holds 1-based page numbers for PDFs; a document whose page numbers are
  not contiguous `1..n` is rejected at construction.
- Scope: `adapters/parser.py`, `tests/test_parser_adapter.py`, `docs/items/AD-07.md`.
- Non-goals: a real HTML converter or MinerU integration, network calls, new dependencies,
  database tables, chunking, stage wiring.
- Acceptance: tests written first, failed with `ModuleNotFoundError: No module named
  'adapters.parser'`. They show protocol conformance (isinstance; mypy via `_conforms()`),
  HTML without pages, PDF with numbered pages, parameter/case-insensitive content-type
  matching, `ParseError` for unsupported types and non-contiguous page numbers, and frozen
  records.
- Scale / memory bound: `parse` holds one document's Markdown and pages in memory. A real
  implementation must cap input size and page count before converting.
- Connections: **unwired by design**. First production caller: the Phase 1 Parse & chunk row
  (HTML + MinerU, heading-aware chunks with provenance).
- Evidence / residuals: round 13, branch `task/ad-07-parser-adapter`, base 57ba142. Gate
  offline: `uv run pytest` → 361 passed, 3 skipped (pre-existing, `DM_TEST_DATABASE_URL`
  unset), 12 new tests; `uv run ruff check .` → passed; `uv run ruff format --check adapters
  tests` → passed; `uv run mypy core adapters` → no issues in 14 files. Residuals: no HTML
  converter or MinerU client, so table preservation, title extraction and page numbering from
  a real source are unverified assumptions; no input-size or page-count cap yet; language
  detection and chunking belong to the Phase 1 Parse & chunk row.

# CR-03: decimal Crawl-delay values

Status and dependencies live in the canonical backlog, not duplicated here.

- Target references: ARCHITECTURE.md §4 (Crawl & snapshot: ``robots.txt,
  per-host rate limit, polite user agent``); CR-02 residual "integer
  Crawl-delay only" (`docs/items/CR-02.md`); D-003 (neutral fixtures:
  `example.com` / `example.org` only).
- Objective: `RobotsPolicy.crawl_delay(url)` returns decimal delays —
  `Crawl-delay: 1.5` → `1.5` for the matching user-agent group — as it already
  does for integers. Invalid, negative, non-finite or absent values → `None`,
  and the blanket cases (no robots.txt, any failure status or raised fetch)
  stay `None`. Allow/deny decisions stay on `urllib.robotparser`; delays are
  parsed from the same 512 KiB-capped body using the stdlib parser's grouping
  and matching semantics: a specific group named for the agent wins over the
  `*` group, and a matching specific group without a delay does not fall back.
  Only plain decimal notation is accepted (`2`, `1.5`, `0.25`); signs,
  exponents, underscores and `inf`/`nan` spellings are invalid. Grouping
  mirrors the stdlib state machine, including `request-rate`-only groups and
  keeping an earlier valid delay when a later value is invalid.
- Scope / non-goals: `adapters/crawl_policy.py`, `tests/test_crawl_policy.py`,
  this file. Non-goals: `core/cli.py`, cache eviction, thread safety,
  `todo.md`.

# AT-11: `landscape attributes-export` lines carry current-row unit

Status and dependencies live in the canonical backlog, not duplicated here.

- Target references: ARCHITECTURE.md §4 stage 8, §5 (`attribute_value.unit`); AGENTS.md
  "Connections", "Scale"; D-003 (neutral fixtures, `scopes/_example` only). Follows AT-10
  (`current_attribute_value_rows_many`, `attribute_evidence_many`) and AT-03 residual
  "no unit ... in the export".
- Objective: each `attributes-export` JSON line gains a last key `"units"`: sorted attribute id →
  the stored `unit` of that attribute's *current* `attribute_value` row (JSON `null` when the row
  has no unit). `entity_id`, `attributes` and `evidence` are unchanged in content and order
  (`units` comes after `evidence`). `core.attribute_store.current_attribute_value_rows_many`
  also returns the row's `unit` (its one production caller `run_attributes_export` is adjusted);
  `current_attribute_values_many` keeps its signature and behaviour. The unit comes from the
  stored row, not the pack. Per ≤500-entity batch query counts are unchanged (no new query).
- Scope / non-goals: export only. No schema change, migration, unit conversion, or other command
  change. Superseded row's unit is not exported.
- Acceptance: `tests/test_cli_attributes_export.py` — `units` maps each exported attribute id to
  its current row's unit; `null` for a unit-less attribute; a superseded row's different unit is
  not exported; `units` is the last key; statement counter over 501 entities still shows 2 value
  and 2 evidence queries. Full gate `uv run pytest -q && uv run ruff check . && uv run mypy core`
  green, plus `uv run ruff format --check` on touched files.
- Connections / scale: no new public symbol; producer is the stored row, consumer the later
  static-site row. Batching unchanged (≤500 ids per query).
- Evidence / residuals: PR for assignment 86/A1; SQLite only, PostgreSQL unexercised, no live
  export run.

# CH-03: chunk row persistence

Status and dependencies live in the canonical backlog (`todo.md`, Phase 1 › Parse).

- Target references: ARCHITECTURE.md §4 (Parse & chunk), §5 `chunk` table; D-003 (neutral
  examples). Builds on CH-01 (`core/chunking.py` `Chunk`) and CH-02 (`core/parse_chunk.py`); follows
  the RT-01 SQLAlchemy pattern (`core/runs.py`).
- Objective: a `chunk` table and `store_chunks(engine, snapshot_id, chunks, *, batch_size=500) -> int`
  in `core/chunk_store.py` that persists an iterable of `Chunk` for one snapshot idempotently:
  re-storing a snapshot replaces its rows, so a retry never duplicates.
- Columns: `id`, `snapshot_id` (integer, indexed; no FK until the snapshot table row lands),
  `seq`, `text`, `lang` (nullable, written NULL until language detection), `page` (nullable),
  `heading_path` (JSON list of strings), `char_start`, `char_end`; unique `(snapshot_id, seq)`.
  No `embedding` column (the Index row adds it).
- Non-goals: CLI `parse` stage wiring (needs snapshots from the Crawl row), snapshot table,
  migrations, language detection, embeddings, edits to `core/chunking.py`/`core/parse_chunk.py`.
- Connections / scale: **unwired by design**; the CLI `parse` stage row wires it once snapshots
  exist. Consumes the chunk iterator lazily, inserting in batches of `batch_size` inside one
  transaction per snapshot (delete-then-insert), holding at most one batch in memory.
- Evidence / residuals: round 19, assignment A1, branch `task/ch-03-chunk-store`, base `07a7549`;
  PR #46. Tests were written first and failed at base with
  `ModuleNotFoundError: No module named 'core.chunk_store'`. Gate on the branch: pytest 433 passed,
  4 PostgreSQL skips; `ruff check` and `mypy core` pass; `ruff format --check .` reports only the
  pre-existing `ARCHITECTURE.md:200` (also fails on a pristine base archive). Negative control:
  removing the delete step fails five idempotency tests. The table reuses `core.runs.Base`, so
  `core.runs.create_all` creates it. Residuals: no migration or snapshot FK, `lang` always NULL,
  the PostgreSQL path is skipped here (`DM_TEST_DATABASE_URL` unset), and the store stays unwired
  until the CLI `parse` stage row.

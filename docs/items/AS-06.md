# AS-06: Hybrid evidence retrieval: cosine vector leg and reciprocal-rank fusion

Status and dependencies live in the canonical backlog, not duplicated here.

- Target references: ARCHITECTURE.md §4 stage 7 (retrieval for a criterion: hybrid BM25 on
  `retrieval_hints` + vector on question → top-k → reranker → top-n chunks per entity × criterion);
  `core/keyword_search.py` (`search_chunks`, IX-03); `core/chunk_store.py` (`ChunkRow.embedding`,
  `embedding_model`); `core/embed_store.py` (IX-01 storage contract); `adapters/embedding.py`
  (`Embedder` protocol, AD-03); D-003 (neutral fixtures only).
- Objective: `core/vector_search.py` exposes `VectorHit` and
  `search_chunks_by_vector(engine, query_vector, *, model, limit, entity_id=None, batch_size=...)`:
  cosine similarity over chunks whose `embedding_model == model` and whose `embedding` is non-null,
  keyset batches by `chunk.id` (bounded memory), a top-`limit` heap with ties by chunk id ascending,
  and `ValueError` on a query/stored dimension mismatch (naming the chunk id, never its text).
  `retrieve_evidence` gains keyword-only `embedder: Embedder | None = None` and `model: str | None =
  None`: with an embedder it embeds the criterion `question`, runs the BM25 leg
  (`build_query`) and the vector leg with `limit=k`, fuses them by reciprocal-rank fusion
  (`k_rrf=60`, ties by chunk id ascending) and cuts to `n`. `model` defaults to `embedder.model`
  and selects the stored embedding model. With `embedder=None` the keyword-only AS-02 path is
  byte-for-byte unchanged.
- Scope / non-goals: `core/vector_search.py`, `core/retrieve.py`, `tests/test_vector_search.py`,
  `tests/test_retrieve.py`, this file, its `todo.md` row. No `core/cli.py` (lane 64/A1 owns it), no
  pgvector/vector index, no reranker, no live embedding calls; no change to `core/keyword_search.py`,
  `core/chunk_store.py` or `core/embed_store.py`.
- Connections: `search_chunks_by_vector` is called by `retrieve_evidence`. The `embedder` argument
  is unwired by design: the later `landscape assess` hybrid retrieval row builds an `Embedder` and
  passes it. The reranker remains a follow-up between top-`k` and top-`n`.
- Scale: both legs scan the O(entity corpus) per query; the vector leg holds one keyset batch plus a
  top-`limit` heap. A pgvector index is later work (residual).
- Acceptance: offline pytest (SQLite fixtures, fake `Embedder`) failing at base and passing at head:
  cosine order and `limit` cap, entity/model filters, skipped null embeddings, page-boundary batch
  sizes agreeing, dimension mismatch `ValueError`, tie order by chunk id; fused retrieval returns
  chunks found by only one leg with the expected RRF order; `embedder=None` output unchanged and the
  existing keyword tests green. Full gate green.

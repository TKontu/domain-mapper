# AS-10: `landscape assess` appends an assessment row and its evidence

Status and dependencies live in the canonical backlog, not duplicated here.

- Target references: ARCHITECTURE.md §4 stage 7 (extract → verify → route) and §5 data model
  (`assessment`, `evidence`; "assessments are append-only" with the current view as a later,
  separate query); `core/assess.py` (`Extraction`, `Quote`), `core/verify.py` (`Route`), `core/runs.py`
  (`Base`, `create_all`), `core/screen_store.py` (store pattern), D-003 (neutral fixtures only).
- Objective: every `landscape assess` that reaches a route (extraction, verification and
  `route` complete, run closed `finished`) appends one `assessment` row and one `evidence` row per
  extractor quote in one transaction through the new `core/assessment_store.py`
  (`AssessmentRow`, `EvidenceRow`, `record_assessment`), before the run closes. The command prints
  `assessment <id>` after the route line. Accept, adjudicate (including checks-failed) and silent
  outcomes are all outcomes and are all persisted; a failed-checks or adjudicate outcome still
  exits 1 as before. `AssessError`/`LlmError`/`EmbeddingError`/`ValueError` paths and setup errors
  (exit 2) write no assessment row.
- Columns written now: `assessment(id, entity_id, criterion_id, status, confidence, rationale,
  rubric_version, extractor_model, verifier_model, decided_by, route_kind, run_id, created_at)`
  and `evidence(id, assessment_id, chunk_id, quote, grounded)`. `confidence` stays NULL this
  stage, `decided_by` is `"auto"` for every row written here, and `route_kind` is
  `accept`/`adjudicate`/`silent`. `rubric_version` records the scope pack's `version`, the only
  version the pack schema carries today; a rubric-only version is a later schema question.
- Out of scope / non-goals: §5 columns that need later stages — `prompt_version` (cache/versioning
  row), `inherited_from_entity_id` (group inheritance) and evidence `source_id`/`source_tier`
  (source catalogue) — plus schema migrations, current-view queries, `claim_check`, `review_item`,
  `ARCHITECTURE.md`, `docs/decisions.md` and any live model or database call. Scope is
  `core/assessment_store.py`, `core/cli.py` (`run_assess` only), `tests/test_assessment_store.py`,
  `tests/test_cli_assess.py`, this file and the AS-10 `todo.md` row.
- Connections / scale: `record_assessment`'s production caller is `run_assess`; `AssessmentRow`
  and `EvidenceRow` consumers (review queue, current-view queries, reporting) are later rows,
  unwired by design. Scale: one assessment row plus at most one evidence row per quote, with the
  quote count bounded by the retrieval `--n` pool.
- Acceptance: offline pytest (SQLite fixtures, existing fake LLM seams) failing at base and passing
  at head — store round-trip with evidence, one-transaction rollback, append-only second write,
  silent outcome without evidence, route kinds; CLI accept path writes one assessment with its
  `run_id`, status, `route_kind accept` and evidence chunk ids and prints `assessment <id>`, silent
  path writes a row with zero evidence, checks-failed path writes a row and still exits 1, and
  extractor/verifier/embedding/rerank error paths write none. Existing assess tests are unchanged
  apart from the new trailing line. Full gate green: `uv run pytest -q && uv run ruff check . &&
  uv run ruff format --check core adapters tests && uv run mypy core`.
- Evidence / residuals: assignment 67/A1 PR #157 (head SHA and gate counts in the PR body).
  Residual: verification is offline SQLite only; no PostgreSQL run, since migrations remain a
  separate item and the tables come from `create_all`.

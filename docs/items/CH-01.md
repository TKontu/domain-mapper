# CH-01: heading-aware Markdown chunker

Status and dependencies live in the canonical backlog (`todo.md`, Phase 1 › Parse).

- Target references: ARCHITECTURE.md §4 (Parse & chunk: heading-aware, ~300–600 tokens, overlap;
  each chunk keeps page, heading path and character offsets) and the `chunk` table shape
  (`seq`, `text`, `page`, `heading_path`, `char_start`, `char_end`); D-003 (no domain words;
  examples neutral).
- Objective: a pure, offline function `chunk_document(doc: ParsedDocument, *, max_tokens=600,
  min_tokens=300, overlap_tokens=60) -> Iterator[Chunk]` in `core/chunking.py` that splits Markdown
  into heading-aware chunks and yields frozen `Chunk` records.
- Semantics:
  - `Chunk` is a frozen dataclass: `seq` (0-based, contiguous), `text`, `page` (`int | None`; `None`
    for documents with no pages), `heading_path` (tuple of ATX heading titles `#`..`######`
    enclosing the chunk, outermost first), `char_start`, `char_end`. Offsets index
    `doc.markdown` when `pages` is empty, otherwise that page's `markdown`; the invariant
    `source[char_start:char_end] == text` always holds.
  - Token count is a deterministic whitespace-split word count (an approximation, documented; no
    tokenizer dependency).
  - A chunk never spans a heading boundary or a page boundary. Each page's Markdown is chunked on
    its own, so the heading path restarts at a page boundary. The heading line is not part of the
    chunk text; `heading_path` carries it.
  - Sections longer than `max_tokens` are split at paragraph (blank-line) boundaries, then at word
    boundaries for an oversized paragraph; consecutive split chunks of one section overlap by
    about `overlap_tokens` words. Adjacent small sections are not merged (that keeps every
    `heading_path` exact); `min_tokens` is only a target for where splitting stops.
  - Headings inside fenced code blocks (``` or ~~~) are not headings. Whitespace-only spans produce
    no chunk; an empty document yields no chunks.
  - Invalid parameters (`max_tokens < 1`, `overlap_tokens < 0`, `overlap_tokens >= max_tokens`,
    `min_tokens > max_tokens`) raise `ValueError` eagerly, before iteration.
- Scope / non-goals: `core/chunking.py`, `tests/test_chunking.py`, this file, and one row under
  `todo.md` Phase 1 › Parse. Non-goals: language detection, DB persistence, `snapshot_id`/URL
  fields (the caller adds them), real parsers, tokenizer dependencies, CLI wiring, any other file.
- Acceptance: tests were written first and failed at base `7dee7e7` with
  `ModuleNotFoundError: No module named 'core.chunking'`. They now show nested heading paths,
  page numbers and per-page offsets for a two-page document, the offset invariant for every chunk
  of every test document, an oversized section split into chunks each `<= max_tokens` words with
  word overlap between neighbours, an oversized paragraph split at word boundaries, fenced
  `# not a heading` ignored (both fence characters), empty and whitespace-only documents yielding
  `[]`, each invalid parameter raising `ValueError`, and contiguous `seq` from 0. Negative
  controls: disabling fence tracking fails the two fence tests (and the mixed-document offset
  test), removing parameter validation fails all six invalid-parameter cases, disabling page
  splitting fails the two-page test, and disabling overlap fails the two split tests. The new
  tests passed five consecutive runs.
- Connections / scale: **unwired by design**; the first production caller is the Phase 1 Parse &
  chunk stage row that stores `chunk` rows. Scale: a generator that holds one document (already
  bounded by the Parser's caps) and emits chunks lazily; no further bound is imposed here.

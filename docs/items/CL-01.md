# CL-01: CLI `crawl` stage for explicit URLs — the first production caller of AD-13, CR-02, RS-01, RS-02, CR-01 and IN-01

Status and dependencies live in the canonical backlog, not duplicated here.

- Target references: ARCHITECTURE.md §4 (Crawl & snapshot); D-005 (raw store root from
  `RAW_STORE_DIR`, default `data/raw/`); D-003 (neutral fixtures). No architecture change.
- Objective: `landscape crawl --scope DIR --url URL [--url URL ...]` (non-dry-run) processes each
  URL sequentially: `HostRateLimiter.wait` → `RobotsPolicy.allowed` (robots.txt via a stdlib GET,
  CR-02 semantics, 512 KiB cap; `Crawl-delay` raises the per-host interval) → `HostRateLimiter.wait`
  → `ingest_page(engine, fetcher=FirecrawlFetcher.from_env(stdlib POST transport),
  parser=HtmlParser(), blob_store=FilesystemBlobStore(raw_store_root(os.environ)))` against
  `Settings.database_url` (tables created with `core.runs.create_all`; no migrations). One line per
  URL: `ok URL snapshot=ID chunks=N raw=DIGEST`, `skipped URL robots` or `error URL ExcType[: msg]`
  (message only for `FetchError`). Exit 1 if any URL failed; exit 2 without `--url`, without
  `FIRECRAWL_URL` or when the database cannot be opened. `--dry-run` prints the existing plan.
  Other stages are unchanged.
- New `adapters/http_transport.py`: `make_post_transport(max_bytes, timeout_s)` reads at most
  `max_bytes + 1` bytes and raises `FetchError` when over (closes AD-13's "caps checked after read"
  residual for this transport); `get_robots` reads at most `MAX_ROBOTS_BYTES`. Non-2xx returns
  `(status, b"")`; http(s) only.
- Scope / non-goals: `core/cli.py` (crawl stage), `adapters/http_transport.py`, tests, this file.
  No entity resolution, scope-pack crawl policy, parse/index stages, concurrency, retries,
  Camoufox/FlareSolverr.
- Acceptance: failing-first tests (`tests/test_cli_crawl.py`, `tests/test_http_transport.py`)
  against a local `http.server` on 127.0.0.1: success (snapshot + chunks + blob), robots disallow
  (no scrape), one `FetchError` URL with others proceeding (exit 1), missing `FIRECRAWL_URL`
  (exit 2), no `--url` (exit 2), transport read cap, env URLs never echoed. One live crawl of
  `https://example.com/` against the configured Firecrawl.
- Evidence / residuals: round 27/A1, branch `task/cl-01-crawl-stage`, base 4bcf239. Live check
  skipped: the operator `.env` has no `FIRECRAWL_URL`, so AD-13 and this row stay partial until a
  live crawl is run. Residuals: user agent and 1 s minimum per-host interval are module constants
  (no config); the robots fetch is spaced by the limiter but Firecrawl's own request to the host is
  not observable; no retries; SQLite/PostgreSQL schema via `create_all` (no migrations);
  `max_crawl_concurrency` unused (sequential).

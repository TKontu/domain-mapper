# RS-02: wire the RS-01 raw blob store into `ingest_page` (D-005)

Status and dependencies live in the canonical backlog, not duplicated here.

- Target references: ARCHITECTURE.md §4 Crawl & snapshot ("Raw bytes stored content-addressed
  (sha256)"); D-005; D-003 (neutral fixtures only); RS-01, CR-01, IN-01.
- Objective: `core.ingest.ingest_page` gains a keyword-only `blob_store: BlobStore | None = None`.
  When given, it calls `blob_store.put(result.body_bytes)` after the fetch and BEFORE
  `record_snapshot`; the returned digest must equal the digest `record_snapshot` stores
  (`hashlib.sha256(body).hexdigest()`), else it raises `BlobStoreError` and no snapshot row is
  written. A `BlobStoreError` from `put` propagates before any row is written. `IngestResult` gains
  `raw_digest: str | None` (None when no store). `None` keeps today's behaviour exactly.
- Scope / non-goals: `core/ingest.py`, `tests/test_ingest.py`. Non-goals: CLI `crawl` stage,
  config.py/env wiring, MinIO, GC, streaming, schema changes.
- Connections: the CLI `crawl`/`parse` stage row is the production caller of the new parameter
  (unwired until then).
- Scale: one body in memory, bounded by the fetcher byte cap (unchanged).
- Acceptance: offline tests with InMemoryFetcher + HtmlParser + SQLite and
  `InMemoryBlobStore`/`FilesystemBlobStore(tmp_path)`: blob retrievable by the snapshot row's
  sha256; `raw_digest` set; no store → `raw_digest is None`, existing tests unchanged; raising `put`
  → no snapshot row; wrong digest → `BlobStoreError`, no snapshot row; FetchError → nothing put.
  `uv run mypy core adapters` passes.
- Evidence / residuals: PR for assignment 25/A1. Residuals: unwired until the CLI crawl stage row;
  a blob may be stored without a snapshot row if `record_snapshot` fails afterwards (orphan, GC is a
  non-goal); not yet seen against a real source.

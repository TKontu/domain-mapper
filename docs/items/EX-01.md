# EX-01: offline M1 example run over scopes/_example

Status and dependencies live in the canonical backlog, not duplicated here.

- Target references: ARCHITECTURE.md §5 (data model) and the M1 milestone; D-003 (neutral
  fixtures only, `scopes/_example`); GV-01/GV-02/GV-03 ratchets. Consumers: FE-01..FE-04, MP-01.
- Objective: one reproducible offline run, `scripts/example_m1_run.py --out DIR`, that starts
  from a fresh SQLite file in `DIR`, seeds entities, screen results and grounded assessments
  through the store APIs (`core.screen_store.record_screen_result`,
  `core.assessment_store.record_assessment`; those stages have no LLM-free CLI), then drives the
  real `landscape` CLI as subprocesses: `presence-set` -> `scores-export` -> `export` ->
  `mosaic` unfiltered and once per scope layer with `--layer`, each with `--entity-dir`. The last
  stdout line is a JSON summary (steps + exit codes, JSONL line counts, mosaic rows/cells).
- Scope / non-goals: the script, `tests/test_example_m1_run.py`, `docs/runs/EX-01.md`. No
  core/app behavior change, no LLM, no network, no Postgres, no browser run.
- Acceptance: the test (failing at base: script absent) runs the script into `tmp_path` and
  asserts exit 0, every step exit 0, mosaic HTML per layer, `--layer` rows equal exactly the
  entities whose `layers` contain that layer, an entity without presence exists and appears only
  unfiltered, and every row links to an entity page in the matching `--entity-dir` whose evidence
  list is nonempty. Full gate green. Run record: `docs/runs/EX-01.md`.
- Residuals: evidence chunk ids are synthetic (no crawled snapshot), so evidence `url` and
  `fetched_at` render empty; segments and assessments are seeded, not screened/assessed by an LLM.

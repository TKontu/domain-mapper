# AD-03: `Embedder` + `Reranker` adapters — local GPU service

Status and dependencies live in the canonical backlog (`todo.md`, Phase 0 › Adapters).

- Target references: ARCHITECTURE.md §6 "Index" (embeddings on a local GPU service → pgvector) and
  the retrieval row (hybrid → top-k → **reranker** → top-n), §6 services table ("Embeddings,
  reranking | local GPU service"); D-003; `core/config.py` (`embedding_url`, `reranker_url`).
- Objective: `adapters/embedding.py` defines an `Embedder` protocol
  `embed(texts: Sequence[str]) -> list[list[float]]` and a `Reranker` protocol
  `rerank(query: str, documents: Sequence[str], top_n: int) -> list[RerankHit]`, where
  `RerankHit(index, score)` names the document's position in the request and its score. HTTP
  implementations post to an OpenAI-compatible `{base}/embeddings` and to `{base}/rerank`; the
  request/response shapes they assume are listed below. Both take an injectable transport callable
  (the stdlib default reuses the `adapters/llm.py` pattern), validate a finite `timeout` and, for
  the embedder, a positive integer `batch_size` at construction. `embed` splits its input into
  `ceil(N / batch_size)` requests and reassembles the vectors in input order. `build_embedder(settings, model)`
  builds against `settings.embedding_url`; `build_reranker(settings, model)` against
  `settings.reranker_url` — `Settings` carries the two services as separate endpoints
  (`DEFAULT_EMBEDDING_URL` port 8001, `DEFAULT_RERANKER_URL` port 8002), so posting `/rerank` to the
  embedder URL would be wrong. Both builders take the model name as an argument; no model name is
  added to `core/config.py`.
- Assumed wire shapes (not yet checked against a live service; see residuals):
  - Embeddings request: `POST {base}/embeddings`, `Content-Type: application/json`, body
    `{"model": <str>, "input": [<str>, ...]}` (one batch per request). Response: 2xx JSON
    `{"data": [{"index": <int>, "embedding": [<float>, ...]}, ...]}`.
  - Embeddings alignment: `data` must have exactly one item per input, `index` must be an integer in
    `[0, len(batch))` and unique, every vector non-empty, all vectors the same width, every value a
    finite number. Vectors are reordered by `index`; anything else raises `EmbeddingShapeError`.
  - Rerank request: `POST {base}/rerank`, body
    `{"model": <str>, "query": <str>, "documents": [<str>, ...], "top_n": <int>}`. Response: 2xx
    JSON `{"results": [{"index": <int>, "relevance_score": <float>}, ...]}` (the shape used by
    Cohere/Jina-style and OpenAI-compatible rerank servers).
  - Rerank alignment: each `index` must be an integer in `[0, len(documents))` and unique, each
    score a finite number. Hits are sorted by score descending (ties keep the service's order) and
    truncated to `top_n`; `top_n` above the number of documents returns every hit, and empty
    `documents` returns `[]` without a request.
- Failure surface: non-2xx raises `EmbeddingError` carrying only the status code and its canned
  reason; transport `OSError`s become `EmbeddingError("transport failed: <type>")`. Neither the
  request text, the query/documents nor the response body is read into an error message, because
  input passages may hold private evidence. Malformed or unalignable bodies raise the subclass
  `EmbeddingShapeError`.
- Scope: `adapters/embedding.py`, `tests/test_embedding_adapter.py`, `docs/items/AD-03.md`.
- Non-goals: real network calls in the gate, pgvector storage or the embedding table, retries,
  caching, edits to `core/config.py`, `pyproject.toml`, `todo.md` or `ARCHITECTURE.md`, CLI or
  stage wiring.
- Acceptance: offline tests with fake transports show (a) each call sends the right URL, headers,
  model and body, and trailing slashes in the base URL are handled; (b) `embed` splits N texts into
  `ceil(N / batch_size)` requests whose bodies partition the input in order and whose returned
  vectors are reassembled in input order; (c) reordered response indices are re-sorted, while a
  count mismatch, missing/invalid/repeated/out-of-range index, empty or non-finite vector,
  inconsistent dimensions, malformed or non-JSON body raise `EmbeddingShapeError`/`EmbeddingError`;
  (d) `rerank` returns `top_n` hits sorted by score descending, clamps a large `top_n`, rejects
  `top_n` that is not an integer >= 1, and rejects out-of-range/repeated indices and malformed or
  non-finite scores; (e) an HTTP error raises `EmbeddingError` with its status and neither the input
  text nor the error body in the message; (f) invalid `batch_size`/`timeout` and blank base
  URL/model are rejected at construction; (g) `build_embedder`/`build_reranker` read the endpoint
  from `Settings` and the model from their argument.
- Scale / memory bound: `embed` keeps one batch request in flight and returns one vector list per
  input; it does not accumulate across calls, but the caller holds every output vector, so a
  streaming caller must chunk its own input (recorded as a residual). The reranker sends one request
  per call with every document in the body, so a caller must bound the document set (top-k) before
  calling. There is no retry, cache or concurrency inside the adapters.
- Connections: **unwired by design**. The first production callers are the Index stage row
  (embedder) and the Assess retrieval row (reranker), which will build the adapters with
  `build_embedder`/`build_reranker`. No CLI or schedule path reaches `adapters/embedding.py` yet.

  PR body records the final head, packet digest and gate output. Local gate offline:
  `uv run pytest` → 290 passed, 3 skipped, 113 subtests passed; `uv run ruff check .` → passed;
  `uv run ruff format --check adapters/embedding.py tests/test_embedding_adapter.py` → passed;

  error bodies are deliberately not read, so provider diagnostics are limited to the status code and

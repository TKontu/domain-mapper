# AS-13: streaming variant of the current assessment view

Status and dependencies live in the canonical backlog, not duplicated here.

- Target references: ARCHITECTURE.md §5 data model; `core/assessment_store.py`
  `current_assessments` (AS-11); `core/cli.py` `run_export` (AS-12); D-003 (neutral fixtures).
- Objective: new `iter_current_assessments(engine, *, entity_id=None, criterion_id=None,
  rubric_version=None, batch_size=500)` in `core/assessment_store.py` yields `CurrentAssessment`
  rows in the same order and with the same filters as `current_assessments`, fetching the ranked
  rows with `yield_per(batch_size)` / `partitions` and their evidence one batch at a time, so at
  most one batch (plus its evidence) is held. `current_assessments` returns
  `list(iter_current_assessments(...))`. `run_export` iterates the generator, so `landscape
  export` writes rows as they stream.
- Scope / non-goals: `core/assessment_store.py`, `core/cli.py` (`run_export` only),
  `tests/test_assessment_store*.py` / `tests/test_cli_export.py`, this file and the AS-13
  `todo.md` row. No schema, migration, output-format or CLI-flag changes.
- Acceptance: offline pytest failing at base and passing at head — generator output equals
  `current_assessments` output (order, filters, evidence) across a fixture with more rows than a
  small `batch_size` (e.g. 2); evidence attached to the right rows across batch boundaries;
  `batch_size < 1` raises `ValueError`; existing AS-11/AS-12 tests still pass. Full gate green.
- Evidence / residuals: assignment 70/A1 PR (head SHA, gate counts). Residuals: SQLite only;
  the database session stays open for the duration of the export.

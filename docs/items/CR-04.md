- Objective: `uv run landscape crawl --scope <dir> [--limit N]` with no `--url` crawls the homepage `https://<primary_domain>/` of each entity of that scope pack id (ordered by entity id, at most N when `--limit` is given), through the same robots/rate-limit/ingest path as `--url`, passing `entity_id=<entity.id>` to `ingest_page`; output lines are unchanged in shape (`ok|skipped|error <url> ...`) and exit codes keep their meaning (1 any failed, 2 bad setup). With no entities it prints `entities 0` and exits 0. With `--url` behaviour is unchanged (entity_id None) and `--limit` is ignored as today.
- In scope: `core/cli.py` `run_crawl` and the crawl command help text; a small helper that pages entity rows by scope id (keyset by id, bounded batch, e.g. in `core/entity_store.py`); tests (fake fetcher/robots seams as the existing crawl CLI tests use). Non-goals: multi-page crawl policy (max pages, priority paths, PDFs), status filtering (no Screen statuses exist yet; crawl all entities of the scope), re-crawl skipping, migrations, entity FK on snapshot.
- Premises: (1) `run_crawl` refuses an empty `--url` list with "entity-driven crawling is not implemented yet": `grep -n "entity-driven" core/cli.py`; (2) `Entity` has `scope_id`, `primary_domain`: `core/entity_store.py`; (3) existing crawl CLI tests inject a fetcher/robots fake: `grep -rln run_crawl tests`.
- Expected files: `core/cli.py` (crawl only), `core/entity_store.py` (read helper), tests. Do not touch resolve, ARCHITECTURE.md, docs/decisions.md, .agent/, .claude/, scripts/.
- Resources / artifacts: none; offline SQLite and fakes only. No network, no live DB, no paid APIs.
- Acceptance: offline tests show — 2 entities in scope S and 1 in scope T → crawl --scope S fetches exactly the two S homepages in id order and the snapshots carry their entity ids; `--limit 1` fetches one; robots disallow still prints `skipped <url> robots`; a fetch error on one entity continues and exits 1; zero entities prints `entities 0` exit 0; `--url` path unchanged (existing tests pass unchanged); a scope-pack load error exits 1 like `resolve --apply`; database errors exit 2 without echoing the URL.

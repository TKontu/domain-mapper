# RV-04: entities created by `resolve --apply` record their run

Status and dependencies live in the canonical backlog, not duplicated here.

- Target references: ARCHITECTURE.md §5 `entity(..., created_run)`; RT-01 run rows (`app.cli._run_resolve_unit` opens a `resolve` run). Conformance fill-in, no design change. Origin: RV-02 residual seen round 152 (docs/runs/PG-152.md): `entity.created_run` stayed NULL.
- Objective: entities created by `landscape resolve --apply` carry `created_run` = the id of that invocation's `resolve` run row; reused (pre-existing) entities keep their original `created_run`.
- Scope / non-goals: `core.resolve.apply_resolution(..., run_id: int | None = None)` sets `created_run` on new `Entity` rows; `_run_resolve_unit` passes its run id; tests. Not: migrations, backfill of existing NULL rows, schema changes, other stages, Postgres runs.
- Acceptance: offline SQLite tests in `tests/test_resolve_apply.py`: (a) `run_id=7` → created_run 7, default None → NULL; (b) second apply with `run_id=8` keeps 7 on the reused entity, 8 on the new one; (c) CLI `resolve --apply` sets created_run to the opened `resolve` run id. Full local gate green.
- Evidence / residuals: PR (round 153/A1). Residuals: no backfill of existing NULL `created_run`; Postgres not re-run.

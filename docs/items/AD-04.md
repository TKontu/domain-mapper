# AD-04: register, tender and publication adapter interfaces

Status and dependencies live in the canonical backlog (`todo.md`, Phase 0 › Adapters).

- Target references: ARCHITECTURE.md §4 (Discover channels: accreditation, professional,
  tender and publication registers; Resolve: business-register ID lookup; Enrich: founding date
  and employees band; Claim verification: confirm/contradict against authoritative registers),
  §5 (`legal_entity` columns; `listed_professional(id, entity_id NULL, name, register,
  register_id, expertise_area, register_url, valid_until)`), §9 (person-level data only from
  public professional registers, limited to what the register lists, linked to a company where
  possible), §10 (per-country/per-site adapter library selected by a scope pack); D-003;
  `adapters/embedding.py` (Protocol + frozen-dataclass house style).
- Objective: `adapters/registers.py` defines five `typing.Protocol` interfaces —
  `BusinessRegister`, `AccreditationRegister`, `ProfessionalRegister`, `TenderSource`,
  `PublicationSource` — each with frozen-dataclass records, one bounded in-memory
  implementation per protocol for tests and the example scope, and a small `RegisterError`.
  Records are source-shaped, never database rows: `BusinessRecord` carries register, register id,
  name, country, founded, employees band, status and source URL; `AccreditationRecord` carries
  organisation, status (`active` / `suspended` / `withdrawn`), scope text, validity and source URL;
  `ListedProfessional` carries exactly the §5 professional columns minus the database surrogate id
  (with an optional `entity_id` link); `TenderAward` carries buyer, supplier, country,
  classification codes, award date, value/currency and source URL; `Publication` carries
  institutions, topics, published date, DOI and source URL.
- Methods:
  - `BusinessRegister.lookup(register_id)`; `search(name, *, country=None, limit=25)`.
  - `AccreditationRegister.lookup(register_id)`; `entries_for(organisation, *, country=None,
    status=None, limit=25)`.
  - `ProfessionalRegister.lookup(register_id)`; `search(name=None, *, expertise_area=None,
    limit=25)`.
  - `TenderSource.award_notices(*, classification_codes=[], keywords=[], country=None,
    since=None, limit=25)`.
  - `PublicationSource.works(*, institution=None, topics=[], since=None, limit=25)`.
- Query semantics: filters of different kinds combine with AND and values within one kind with
  OR. Text filters are case-insensitive substring matches; tender classification codes match by
  prefix, so a coarse code selects its narrower children. An absent filter is not a filter;
  empty tender filters match every notice and empty publication filters match every work.
  `lookup` returns `None` when the id is absent. Blank ids/names/terms, a non-positive or
  non-integer `limit`, bare strings where a sequence is expected, and non-`date` values raise
  `ValueError`/`TypeError`; two records with the same identity raise `RegisterError`.
- Scope: `adapters/registers.py`, `tests/test_register_adapters.py`, `docs/items/AD-04.md`, the
  single AD-04 row in `todo.md`.
- Non-goals: any real per-country or per-site implementation, network calls, retries, rate
  limiting, caching, database tables or migrations, stage/CLI wiring, changes to `core/`,
  `pyproject.toml`, `uv.lock` or `ARCHITECTURE.md`.
- Acceptance: tests were written first and failed with `ModuleNotFoundError: No module named
  'adapters.registers'`. Offline tests show (a) every in-memory implementation satisfies its
  `runtime_checkable` protocol and a class without the method does not; (b) business lookup returns
  every field and `None` on a miss, and search filters by case-insensitive name and country;
  (c) accreditation entries preserve active/suspended/withdrawn status and scope text and filter on
  both; (d) `ListedProfessional` exposes exactly the §5 columns and no other person-level field;
  (e) tender notices filter by code prefix, keyword in title/buyer/supplier, country and `since`,
  combine filters correctly and keep decimal award values; (f) works filter by institution, topic
  and `since`; (g) every search respects `limit` and the default bound; (h) invalid arguments and
  duplicate record identities are rejected; (i) records are frozen and collection fields are
  tuples. Guards were mutation-checked (duplicate-id rejection, limit slicing, country, status,
  expertise-area, keyword and `since` filters each fail a test when removed), and the adapter suite
  ran five times without flakiness.
- Scale / memory bound: every search returns a materialised `list` of at most `limit` records
  (default 25) and iterates the in-memory records in registration order, scanning until the bound
  is reached; the fakes hold their whole fixture list in memory, which is acceptable for tests and
  the example scope only. A production adapter must push filtering and pagination to the source
  and return at most `limit` records rather than materialising a register; `lookup` is a single
  record. There is no cache or concurrency in these adapters.
- Connections: **unwired by design**. No CLI, stage or schedule path imports `adapters.registers`
  yet. The first production callers are the Phase 1 rows Discover (register/tender/publication
  channels), Resolve (business-register ID lookup), Enrich (register financial data) and Claim
  verification framework + first register verifier (accreditation, professional and tender
  evidence), which will select an adapter per source from the scope pack's catalogue (`source`).
- Evidence / residuals: round 9, branch `task/ad-04-register-interfaces`, base d0d4afb; the PR
  body records the final head, packet digest and gate output. Local gate offline: `uv run pytest`
  → 330 passed, 3 skipped, 126 subtests passed; `uv run ruff check .` → passed;
  `uv run ruff format --check adapters/registers.py tests/test_register_adapters.py` → passed;
  `uv run mypy core adapters` → no issues in 12 source files. Residuals: no real register, tender
  portal or publication index is contacted or implemented, so record shapes and query capabilities
  are engine-side assumptions to be checked against each source's terms and API; the fakes are
  linear scans over a fixed list; there is no pagination, retry, rate limiting, caching,
  provenance logging or source-terms enforcement inside the adapters (the caller and the source
  catalogue own those); person-level output is limited to the §5 columns but a scope pack must
  still supply its legitimate-interest note before collection (§9); nothing is wired into Discover,
  Resolve, Enrich or Claim verification yet. The packet's `uv run ruff format --check adapters
  tests` is red on nine pre-existing test files outside this item's scope (baseline at d0d4afb);
  the two files this item touches are formatted, and the full-tree failure is recorded here as a
  baseline residual rather than reformatted in this PR.

# LM-01: optional local output-token cap

Status and dependencies live in the canonical backlog, not duplicated here.

- Target references: round 123 CO-01 cost report on the live118-m1 DB (assess_verify mean latency
  720 s, max 900 s = the per-call timeout; verifier output is only `{agree, reason}`, so unbounded
  generation is the likely cost); ARCHITECTURE §6 (local verifier routing); LL-02 settings pattern.
- Objective: `Settings.local_max_tokens` from `DM_LOCAL_MAX_TOKENS` and `Settings.verifier_max_tokens`
  from `DM_VERIFIER_MAX_TOKENS` (`int | None`, default None = no cap; non-integer or <=0 raises
  ValueError naming the variable). `OpenAICompatibleLLM(max_tokens=)` sends `"max_tokens"` only when
  set; `build_llm(max_tokens=)` passes it to the local backend (cloud keeps its own). Screen/assess
  seams pass `local_max_tokens`; verify passes `verifier_max_tokens`, else `local_max_tokens`.
- Acceptance: settings tests (unset, 512, abc, 0, -3) for both vars; payload test with and without
  the cap; one spy test per seam incl. verifier override and fallback. Full gate green.
- Residuals: not seen live; the next live M1 run sets `DM_VERIFIER_MAX_TOKENS`.

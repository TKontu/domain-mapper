# AD-02: `source` catalogue seeded from a scope pack

Status and dependencies live in the canonical backlog (`todo.md`, Phase 0 › Adapters).

- Target references: ARCHITECTURE.md §5 (`source(id, name, roles, access_class, licence,
  base_url, adapter)`), §3; D-003.
- Objective: `core/source_catalogue.py` adds a SQLAlchemy `source` table to the existing
  `core.runs.Base` metadata and a `seed_sources(engine, pack)` function that upserts a loaded
  `ScopePack`'s `sources` in one transaction: a new entry is inserted, a changed entry updates its
  row in place, and an unchanged entry writes nothing. Re-seeding the same pack therefore changes
  no rows, and `core.runs.create_all` creates the table.
- Scope: `core/source_catalogue.py`; `tests/test_source_catalogue.py` (fixture packs are written
  under `tmp_path`; `scopes/_example/` is untouched because SP-04 owns it); this file; the single
  AD-02 row in `todo.md`. Non-goals: `core/scope_pack.py` model changes, a CLI command, Discover
  wiring, migrations tooling, retiring rows.
- Mapping choices (stated per the assignment):
  - `Source.role` → `roles`, a JSON list (one element today; the list shape is §5's, so a later
    item can add roles without a schema change).
  - `Source.access` → `access_class` (NULL when the pack omits it); `Source.licence` → `licence`;
    `Source.adapter` → `adapter`.
  - `name` = `params["name"]` when present, else the pack source id; `base_url` =
    `params["base_url"]` when present, else NULL.
  - `countries` and any other `params` keys are not persisted: §5 has no column for them. Recorded
    as a residual, not a silent drop.
  - Row key: the primary key is `(scope_id, id)`, with `scope_id` from `pack.scope.id`. Pack source
    ids are pack-local and two packs can legitimately name the same source (for example a public
    discovery channel), so a bare `id` key would let one pack's seed overwrite another's row.
  - An entry removed from the pack keeps its row: candidates may reference it, and retirement is a
    later decision. Seeding never deletes.
- Scale / transaction bound: source lists are tens of entries; one transaction per seed covers the
  whole pack, and only the target scope's rows are selected. No batching or streaming is needed at
  this size; a larger catalogue would need chunking and is not claimed.
- Connections: `seed_sources` is **unwired by design**; its first production caller is the Phase 1
  Discover row, which will seed the catalogue through the CLI before retrieval. No CLI command is
  added here.
- Evidence / residuals: round 7, assignment A2, PR #20. Box: SQLite in-memory only (Postgres is
  a residual). Seen: `uv run pytest tests/test_source_catalogue.py -q` →
  `9 passed, 1 skipped in 0.34s`; the skip is the optional PostgreSQL class
  ("DM_TEST_DATABASE_URL is not set; PostgreSQL path not exercised"). The suite covers
  `create_all` creating the table, insert with the mapping above, idempotent re-seed (asserted to
  issue no INSERT/UPDATE/DELETE statements), update on change, an added entry, a removed entry,
  two scopes sharing a source id, and an empty pack. Guard negative controls: with the
  change-check mutated to always update, 5 tests fail including `test_reseed_writes_nothing`; with
  `scope_id` out of the primary key, the key-scope and two-scope tests fail. The new file passed
  5/5 repeat runs on SQLite. Residuals: PostgreSQL path unexercised; `countries`/other `params`
  not persisted; removed entries are not retired; no migration tooling (the interim `create_all`
  path, as in RT-01).

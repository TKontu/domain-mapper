# CR-02: crawl politeness policy — robots.txt and per-host rate limit

Status and dependencies live in the canonical backlog, not duplicated here.

- Target references: ARCHITECTURE.md §4 (Crawl & snapshot: "robots.txt, per-host rate limit,
  polite user agent"), §9 (Legal & ethical constraints: "Respect robots.txt, rate limits and site
  terms"); D-003 (neutral fixtures: `example.com` / `example.org` only).
- Objective: new `adapters/crawl_policy.py` with (a) `RobotsPolicy(fetch_robots, user_agent)` where
  `fetch_robots: Callable[[str], tuple[int, bytes]]` takes a robots.txt URL and returns (status,
  body); `allowed(url) -> bool` uses `urllib.robotparser`, caches one parse per scheme+host(+port),
  treats 404/410 as allow-all, 401/403 as disallow-all, other 5xx or a raised exception as
  disallow-all for that host (conservative), and caps the body read at 512 KiB; `crawl_delay(url) ->
  float | None` from robots `Crawl-delay`; (b) `HostRateLimiter(min_interval: float, clock, sleep)`
  with injected monotonic clock and sleep; `wait(url)` sleeps just long enough that two calls for the
  same host are at least `max(min_interval, per-host override)` apart, different hosts never wait for
  each other; `set_interval(host, seconds)` sets an override (e.g. from crawl_delay); (c)
  `CrawlPolicyError`. No network in the module: fetch is injected.
- Scope / non-goals: new `adapters/crawl_policy.py`, new `tests/test_crawl_policy.py`, this file.
  Non-goals: wiring into `ingest_page` or a crawler, per-entity max pages/priority paths,
  user-agent configuration in `config.py`, thread safety (residual). `todo.md`, `core/` and
  `adapters/fetcher.py` are untouched.
- Design notes: any 2xx status is parsed; 404/410 allow all; 401/403 and every other non-2xx status
  (5xx, redirects, other 4xx) disallow all for that origin, and a `fetch_robots` exception is
  treated the same way. Blanket decisions are cached like a parse, so a failing host is fetched once
  per policy object. Only the first 512 KiB of the body is decoded (UTF-8 with replacement) and
  parsed, so rules beyond the cap are ignored rather than buffered. The robots URL is rebuilt from
  scheme + host + port, so userinfo/query/fragment never leak into it. `set_interval` takes a bare
  hostname (no port, as in `urlsplit(url).hostname`) and can only raise the spacing, never lower it
  below `min_interval`.
- Connections: **unwired by design**; the CLI `crawl` stage row is the production caller.
- Scale: the robots cache grows one entry per origin per run (bounded by hosts crawled; residual:
  no eviction). The rate limiter keeps one timestamp per host and one float per override. No layer
  is held in memory; one robots body up to the 512 KiB cap is decoded per origin.
- Acceptance: tests written first and seen failing with `ModuleNotFoundError: No module named
  'adapters.crawl_policy'`; fake fetch and fake clock/sleep only (no real sleeping, no network).
  Cover: allow/disallow by path and user agent; one fetch per host (cache); 404/410 → allow-all;
  401/403 → disallow-all; other statuses and a raised exception → disallow (and cached); oversized
  and invalid-UTF-8 bodies handled and rules beyond the cap ignored; crawl_delay parsed; rate
  limiter same-host spacing, different hosts independent, override respected, first call never
  sleeps; invalid URLs/intervals rejected. `uv run mypy core adapters` passes.

# GS-01: pick and freeze a blind gold-set cell file

Status and dependencies live in the canonical backlog, not duplicated here.

- Target references: ARCHITECTURE.md §7 (eval), D-003 (private scopes); operator ruling 2026-11-28.
- Objective: `landscape gold-pick --scope DIR --out DIR [--entities N] [--per-entity K]` reads a run
  DB's current assessments and writes `cells.jsonl`: one line per chosen (entity, criterion) with
  a stable cell id, primary_domain, criterion id, criterion text and the frozen evidence (chunk
  text, URL, snapshot fetch date). Model status and confidence go only to a separate
  `cells.key.jsonl`, never into `cells.jsonl` (blind). Selection is deterministic, prefers cells
  with readable evidence and spreads over statuses.
- Operator ruling 2026-11-28: ~30-40 cells (~8 entities x 4-5 criteria), clean inputs only, spread
  over statuses, evidence frozen, labeller blind to model status. Optional `--clean` makes one
  cloud call per candidate (at most 2 x target) to reject unreadable/ambiguous cells and trim
  evidence to verbatim passages; every call is logged as `llm_call` under a `gold-pick` run row
  and capped cumulatively by `DM_LLM_BUDGET_USD` (zero budget or zero cloud rates refuse).
- Scope / non-goals: engine code and offline tests on `scopes/_example` fixtures. No network in
  tests; no DB writes except the `--clean` run row and its `llm_call` rows. The real pick on the M1 DB is a later planner lane whose output
  lands only in the private scope repo.
- Acceptance: offline tests for blindness, determinism, status spread and evidence freezing; full
  local gate green.
- Evidence / residuals: `core/gold_pick.py`, `landscape gold-pick`, `tests/test_gold_pick.py`
  (offline, fake transport). Real pick on the run DB not yet run (later planner lane; output lands
  only in the private scope repo). Status/confidence in `cells.key.jsonl` are LLM-built.

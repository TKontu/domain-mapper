# AT-08: `landscape attributes-extract --all` batch mode

Status and dependencies live in the canonical backlog, not duplicated here.

- Target references: ARCHITECTURE.md §4 stage 8 (content attributes via structured extraction),
  §5 (`attribute_value`, `evidence`), §6 LLM routing (local extractor); AGENTS.md "Connections",
  "Scale"; D-003 (neutral fixtures only, `scopes/_example`). Follows AT-07
  (`landscape attributes-extract`, single entity × attribute; residual "single entity per call").
- Objective: add `--all` to `landscape attributes-extract`. With `--all` (and no `--entity`), the
  command iterates the scope's entities with status `in_scope` via
  `core.entity_store.iter_entities(engine, pack.scope.id, status=STATUS_IN_SCOPE, limit=--limit)`
  (keyset paging, never holding the whole scope) and, for each entity, every pack attribute (or
  only `--attribute A` when given). One `attributes_extract` run row covers the whole batch. Per
  entity × attribute: the same BM25 retrieval (`core.keyword_search.search_chunks` on
  `core.attribute_extract.attribute_query`, up to `--n`), one
  `core.attribute_extract.extract_attribute` call and `store_attribute_extraction` in its own
  committed transaction (one transaction per pair; a failure in one pair does not roll back
  earlier pairs). The per-pair work is factored out of `run_attributes_extract` into the shared
  helper `_extract_pair`, called by both single and batch modes; single-entity behaviour and
  output are unchanged. Batch output: one line per pair `entity E attribute A value <json|null>
  checks pass|fail chunks N attribute_value ID|-` (or `entity E attribute A error <Class>: msg`
  for `AttributeExtractError`/`LlmError`, which is recorded and the batch continues), then a
  summary `pairs P stored S null U failed F errors X`. Exit 0 when no pair failed checks or
  errored, 1 otherwise (run closed `finished` when the batch completes, even with failed pairs);
  2 on bad input: `--all` together with `--entity`, neither given, unknown `--attribute`,
  `--n < 1`, `--limit < 1`. `--limit L` caps entities (not pairs). `--dry-run` unchanged.
- Scope / non-goals: in-scope entities only; BM25 only; sequential calls. Non-goals: concurrency,
  skipping already-extracted values (re-runs re-extract; see residuals), hybrid/rerank retrieval,
  verifier pass, export changes, migrations, live model calls. Files: `core/cli.py`,
  `tests/test_cli_attributes_extract.py`, this file and the AT-08 `todo.md` row.
- Connections / scale: `--all` is the production entry point for batch extraction; the shared
  helper `_extract_pair`'s callers are both modes (`run_attributes_extract` single and
  `_run_attributes_extract_batch`). `_extract_pair` remains the production caller of
  `extract_attribute`, `store_attribute_extraction` and `attribute_query`;
  `_run_attributes_extract_batch` is the production caller of `iter_entities(..., status=...,
  limit=...)`. Memory bounded by keyset paging of entities and `--n` chunks per call; LLM spend
  bounded by entities × attributes (cap with `--limit`); one transaction per pair.
- Acceptance: offline pytest failing at base, passing at head (SQLite, fake LLM via monkeypatched
  `_make_assess_llm`) — two in-scope entities and one out-of-scope entity with chunks, pack with
  two attributes: `--all` makes exactly 4 LLM calls (none for the out-of-scope entity), stores
  values with evidence, one run row `finished`, summary line correct, exit 0; `--all --attribute
  A` makes 2 calls; `--limit 1` covers one entity; a fake raising `LlmError` for one pair prints
  its error line, later pairs still stored, exit 1, run `finished`; an ungrounded pair exits 1
  with that pair not written and others written; `--all --entity` exits 2 with no run row;
  `--n < 1`, `--limit < 1`, unknown `--attribute`, neither `--all` nor `--entity` exit 2 with no
  run row; existing single-entity tests unchanged and passing. Full gate green.
- Evidence / residuals: assignment 83/A1; the PR body carries the head SHA and gate counts.
  Residuals: SQLite only, PostgreSQL unexercised; no live model call (tests use a fake `LLM`);
  BM25 only; sequential calls; re-runs re-extract (no skipping already-extracted values).

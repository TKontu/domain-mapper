# AG-06: export evidence carries its source snapshot

Status and dependencies live in the canonical backlog, not duplicated here.

- Target references: ARCHITECTURE.md §10 (Aggregate & score) and its evidence/provenance sections;
  AS-11/AS-12 (`iter_current_assessments`, `landscape export`); D-003 (neutral fixtures only,
  `scopes/_example`). M1 path: the frontend cell click shows status, quote, URL and snapshot date
  (todo.md "Minimal frontend").
- Objective: every evidence object in `landscape export --format json` carries its source:
  `"snapshot_id"`, `"url"` (the snapshot's `final_url`) and `"fetched_at"` (ISO-8601 UTC) alongside
  `chunk_id`, `quote`, `grounded`; all three are `null` when the chunk or snapshot row is missing.
- Scope / non-goals: `CurrentEvidence` gains `snapshot_id`, `url`, `fetched_at` (default `None`),
  filled in `_evidence_for` by LEFT OUTER JOIN evidence -> chunk -> snapshot inside the existing
  per-batch query; `app/cli.py::_export_object` emits them. Non-goals: schema change, migrations,
  scores-export shape, `landscape assessments` text output, frontend code, attribute export
  (attribute evidence carries nulls).
- Acceptance: offline pytest failing at base, passing at head: exported evidence with a stored chunk
  and snapshot carries the snapshot's id, final_url and fetched_at; evidence whose chunk or snapshot
  is absent exports the three keys as null; existing export tests pass with the new keys. Full gate
  green, both ratchets pass.
- Evidence / residuals: round 105/A2 PR (see todo.md); PostgreSQL unexercised; producer for the
  later frontend row (consumer unwired by design).

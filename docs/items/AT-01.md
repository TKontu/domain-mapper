# AT-01: typed attribute values stored with their unit

Status and dependencies live in the canonical backlog, not duplicated here.

- Target references: ARCHITECTURE.md §2 (Attribute: typed int/float/enum/bool/date fact with
  evidence), §4 stage 8 (Quantitative attributes), §5 (`attribute_value(id, entity_id,
  attribute_id, value_json, unit, confidence, run_id)`); `core/scope_pack.py` (`Attribute`,
  `Attributes`); `core/runs.py` (`Base`, `create_all`); `core/screen_store.py` (store pattern);
  D-003 (neutral fixtures only, `scopes/_example`).
- Objective: new `core/attribute_store.py` with an `attribute_value` table on `core.runs.Base`
  (created by `core.runs.create_all`) and `record_attribute_value(session, entity_id, attribute,
  value, *, confidence=None, run_id=None) -> int` that validates `value` against the pack
  `core.scope_pack.Attribute`, appends one row with `value_json` and the attribute's `unit`,
  flushes and returns its id.
- Validation policy: int takes an `int` only, never `bool`; float takes an `int` or finite
  `float`, never `bool`, and stores it as a float; enum takes a `str` and, when the attribute
  lists `values`, must be one of them; bool takes a `bool` only; date takes an ISO 8601 date
  string or a `datetime.date`, never a `datetime`, and stores the ISO date string. Any other
  value raises `ValueError` before the session is touched, so nothing is written.
- Scope / non-goals: storage + validation only. No extraction, no CLI command, no evidence
  linkage rows (`evidence.attribute_value_id`), no export, no migration framework, no change to
  existing tables or `core/cli.py`. Files: `core/attribute_store.py`,
  `tests/test_attribute_store.py`, this file and the AT-01 `todo.md` row.
- Current view: `current_attribute_values(session, entity_id) -> dict[str, Any]` returns the
  latest row (highest `id`) per `attribute_id` with its decoded JSON value, for that entity only;
  an entity with no values yields `{}`.
- Connections / scale: both functions are unwired by design; AT-02 (attribute extraction) is
  their production caller, and the export/frontend rows are later consumers. One entity's rows
  per query; `current_attribute_values` reads only the newest row per attribute through a
  grouped max-id join, never the whole table.
- Acceptance: offline pytest failing at base and passing at head — each type accepts a valid
  value and round-trips (including the attribute's unit); wrong type, an enum value outside
  `values`, a bool given for int and a malformed date raise `ValueError` and write nothing; the
  latest value wins per attribute; other entities' values are not returned. Full gate green.

  counts.
  Residuals: SQLite only, the PostgreSQL path is unexercised; no migration for the new table
  (`create_all` only); no evidence linkage yet.

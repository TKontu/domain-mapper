# CR-06: same-host link discovery within the per-entity crawl budget

Status and dependencies live in the canonical backlog, not duplicated here.

- Item and complete detail: CR-06 (new; this detail is copied to docs/items/CR-06.md at reconcile). todo.md Phase 1 Crawl row; builds on CR-05 (`core/scope_pack.py` `CrawlPolicy`, `core/cli.py` `_entity_targets`/`_crawl_targets`, PR #86).
- Architecture sections / approved decisions: ARCHITECTURE.md §4 stage 4 Crawl & snapshot (per-entity crawl policy: max pages, priority URL patterns); D-003 (tests and examples use `example.com`/`.invalid` hosts and neutral words only); D-005 raw store.
- Objective: `CrawlPolicy` gains `discover_links: bool` (default false). When true, entity crawl fills the remaining `max_pages` budget per entity, after the homepage and priority paths, with same-host links found in that entity's fetched HTML pages, breadth-first in document order. Also: a priority path equal to `/` is rejected (it duplicates the homepage; a CR-05 residual), and a URL is never fetched twice for the same entity.
- In scope: `core/scope_pack.py` (field + `/` rejection), `core/cli.py` entity crawl (targets may now depend on fetched pages), a small stdlib link extractor (e.g. `core/links.py` using `html.parser`: `<a href>` only, resolved against the page's final URL, keep only `https`/`http` on exactly the entity's primary domain host, drop fragments, drop query strings, skip obvious non-HTML extensions such as .pdf .jpg .png .zip, normalise so `/x` and `/x#y` are one URL), `scopes/_example/scope.yaml` (may set `discover_links: true` illustratively), tests. Non-goals: subdomains, sitemaps, PDFs, depth limits beyond the page budget, re-crawl skipping, migrations, changing `--url` mode or `ingest_page`'s public signature unless a minimal additive return is needed (if `ingest_page` must expose the fetched body or links, add it additively and keep existing callers/tests passing).
- Premises: (1) `grep -n "_entity_targets" core/cli.py` shows a static generator built before fetching; (2) `grep -n "discover" core/scope_pack.py` is empty; (3) `uv run landscape validate --scope scopes/_example` passes on base.
- Expected files: `core/scope_pack.py`, `core/cli.py`, a new `core/links.py` (or similar), possibly `core/ingest.py` (additive), `scopes/_example/scope.yaml`, tests. Do not touch ARCHITECTURE.md, docs/decisions.md, todo.md, .agent/, .claude/, scripts/.
- Resources / artifacts: none; offline SQLite and fakes only (existing crawl CLI test seams). No network, no live DB, no paid APIs.
- Acceptance: offline tests show — `discover_links` absent/false → exactly CR-05 behaviour (existing tests unchanged); `max_pages: 4, priority_paths: [/a], discover_links: true` with a homepage linking `/b`, `https://other.invalid/x`, `/a`, `/c#frag`, `/d.pdf`, `/b` → fetched in order homepage, /a, /b, /c, all with the entity's id, nothing off-host, no repeat; links discovered on a robots-disallowed or failed page are not used (nothing fetched from them) and the crawl continues; budget is per entity and `--limit` still counts entities; `priority_paths: ["/"]` fails `load_scope_pack` with a ScopePackError naming the field; extractor unit tests cover relative/absolute/protocol-relative hrefs, base final URL after redirect, malformed hrefs ignored; `uv run landscape validate --scope scopes/_example` exits 0.
- Connections / scale: production caller of the extractor is the entity crawl in `core/cli.py`; per entity hold at most `max_pages` (≤50) URLs in the frontier/seen set plus links parsed from one page at a time, with links per page capped (e.g. first 500 hrefs) — state the cap; entities still paged lazily; per-host rate limit and robots unchanged.

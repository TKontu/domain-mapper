# MG-02: merge_guard accepts records-only reconcile PRs on head-bound reconcile evidence

Status and dependencies live in the canonical backlog, not duplicated here.

- Target references: D-002 (`docs/decisions.md`), MG-01 (`docs/items/MG-01.md`). Requested by the
  loop manager 2026-11-28.
- Objective: MG-01 refused every records-only reconcile PR (cut from main after the round's merges,
  so it never has a ledger result at the round base), deadlocking reconcile.
  `scripts/merge_guard.py PR --head SHA` also accepts a PR whose changed files are all
  reconciliation records (`todo.md`, `docs/items/**`, `docs/runs/**`, `docs/reconcile*`) when
  `.agent-runs/<round>/reconcile-<sha12>.json` (written by
  `scripts/round.py reconcile-result ROUND --head SHA --result FILE`) holds a result for exactly that
  head whose checks all passed and cover pytest, ruff check, ruff format --check and mypy. Lookup
  is by head across rounds; no base equality.
- Scope / non-goals: failed CI still refuses; any file outside the allowlist falls back to MG-01's
  ledger rule unchanged; operator-path refusals unchanged and win. No CI change, no extra globs.
- Acceptance: unit tests in `tests/test_merge_guard.py::RecordsOnlyTests` and
  `tests/test_round.py` (reconcile-result); gate green. Behaviour is seen only on a real
  `/merge-round` of a reconcile PR.
- Evidence / residuals: PR (operator-parked, touches `scripts/merge_guard.py`). Residual: the
  production path (planner's /merge-round on a reconcile PR) is not yet exercised.

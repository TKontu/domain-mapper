# AD-13: `FirecrawlFetcher` — Firecrawl `/v1/scrape` implementation of the `Fetcher` protocol

Status and dependencies live in the canonical backlog, not duplicated here.

- Target references: ARCHITECTURE.md §4 (Crawl & snapshot) fixes `fetch(url, *, render_js=False)
  -> FetchResult`; D-005 (raw bytes go to the blob store via RS-02, so the raw HTML must be kept);
  D-003 (neutral fixtures: example.com / example.org only; no real hosts, IPs or ports in tracked
  files).
- Objective: new `adapters/firecrawl.py` with `FirecrawlFetcher(base_url, transport, *, max_bytes=
  DEFAULT_MAX_BYTES, timeout_ms=DEFAULT_TIMEOUT_MS)`, where `transport: Callable[[str, bytes,
  Mapping[str, str]], tuple[int, bytes]]` POSTs a JSON body to a URL and returns (HTTP status,
  response bytes). `fetch` posts `{"url": url, "formats": ["rawHtml"], "timeout": timeout_ms}` to
  `<base_url>/v1/scrape`; Firecrawl always renders JavaScript, so `render_js` (both values) is
  accepted for protocol conformance and maps to no request option (no `waitFor` tuning). Parses
  `{success, data: {rawHtml, metadata: {statusCode, url|sourceURL, contentType?}}}`; maps
  `rawHtml` UTF-8 bytes to `FetchResult.body_bytes`, `metadata.statusCode` to `status` (the
  transport's 2xx status only when the field is absent or not an integer), final URL from
  `metadata.url` then `metadata.sourceURL`, falling back to the request URL, and content type
  from `metadata.contentType` or `text/html; charset=utf-8`. `FetchResult.headers` is empty
  because the Firecrawl envelope carries no response headers. Raises `FetchError` for: non-http(s)
  request URL, transport exception (type name only), non-2xx transport status, `success: false`
  (include its `error` text, truncated at 200 characters), malformed/non-JSON response, missing or
  non-string `rawHtml`, response bytes over the response cap, and `rawHtml` over `max_bytes`.
  `FirecrawlFetcher.from_env(transport, *, max_bytes=..., timeout_ms=...)` reads `FIRECRAWL_URL`
  from the process environment (`os.environ`; the `DM_*` pattern in `core/config.py` does not
  cover adapter variables), raising `ValueError` naming `FIRECRAWL_URL` when it is unset or blank;
  the host is never hard-coded. Invalid `base_url`, `max_bytes` or `timeout_ms` raise `ValueError`;
  `repr` hides the base URL.
- Scope / non-goals: new `adapters/firecrawl.py`, new `tests/test_firecrawl.py`, this file, and
  one `FIRECRAWL_URL=` placeholder line in `.env.example`. No robots / rate limiting (CR-02 stays
  the caller's job), no real HTTP transport implementation beyond the injected callable, no
  crawler wiring, no Camoufox/FlareSolverr, no live Firecrawl calls in tests (fake transport only).
- Connections: **unwired by design**; the CLI `crawl` stage row is the production caller.
- Scale: one response held in memory, bounded by a response cap of
  `2 * max_bytes + 64 KiB` (JSON escaping plus envelope) with `rawHtml` additionally capped at
  `max_bytes`. Residual: Firecrawl returns the whole body in JSON, so both caps are checked after
  the transport read unless the transport itself streams with a cap.
- Acceptance: tests written first and seen failing with `ModuleNotFoundError: No module named
  'adapters.firecrawl'`; a fake transport records the request URL, body and headers. Tests cover
  the request URL/body/headers and default/custom timeout, trailing-slash base and `from_env`,
  happy-path field mapping, `isinstance(f, Fetcher)`, `sha256` equal to the hash of the rawHtml
  bytes, final-URL/content-type/status fallbacks, `render_js` leaving the request unchanged, empty
  rawHtml, every `FetchError` case above, constructor validation, hidden `repr`, and no network
  (`urlopen` patched to fail).
- Evidence / residuals: round 26/A1, branch `task/ad-13-firecrawl-fetcher`, base 245928a. Offline
  gate at the candidate head: `uv run pytest` → 695 passed, 5 skipped (pre-existing,
  `DM_TEST_DATABASE_URL` unset; PostgreSQL paths not exercised), 130 subtests; `uv run ruff check
  .` passed; `uv run ruff format --check adapters tests/test_firecrawl.py` passed; `uv run mypy
  core adapters` no issues in 25 source files. Residuals: never exercised against a live Firecrawl
  instance (response shape read from the local reference checkout; tests use a fake transport);
  the response/body caps apply after the transport read unless the transport streams; no bundled
  HTTP transport (the wiring row supplies one); transport exception messages are not surfaced,
  only the exception type.

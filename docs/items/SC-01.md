# SC-01: `screen_entity` relevance and segment classifier core

Status and dependencies live in the canonical backlog (`todo.md`, Phase 1 › Screen).

- Target references: ARCHITECTURE.md §4 stage 3 (Screen & classify), §6 model routing; AD-01 (`LLM` protocol); D-003.
- Objective: `core.screen.screen_entity(llm, scope, *, name, domain, text, run_id, max_chars=8000) -> ScreenResult` classifies one entity from already-fetched page text through `LLM.complete(..., purpose="screen", json_schema=screen_schema(scope))`.
- Semantics: segments are the scope's ids in scope-pack order, deduplicated, dropped when out of scope; confidence in [0, 1]; reason trimmed and cut to 500 chars; `borderline` when `0.35 <= confidence < 0.65` or in scope with no segments. Invalid model output (missing key, wrong type, unknown segment, NaN/out-of-range confidence, empty reason) raises `ScreenError(ValueError)` naming the field only. `LlmError` propagates.
- Scope: `core/screen.py`, `tests/test_screen.py`. Public helpers `screen_schema`, `build_prompt` (beyond the packet, accepted at review).
- Connections / scale: unwired by design; production caller is SC-02 (CLI `landscape screen`). One entity per call; prompt bounded by `max_chars` plus segment definitions.

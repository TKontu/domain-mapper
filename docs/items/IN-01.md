# IN-01: `ingest_page` single-page fetch → snapshot → parse → chunk rows

Status and dependencies live in the canonical backlog, not duplicated here.

- Target references: ARCHITECTURE.md §4 Crawl & snapshot and Parse & chunk, §5; CR-01, CH-02, CH-03,
  AD-06/AD-08, AD-10; D-003 (neutral fixtures only).
- Objective: `core/ingest.py` exposes `ingest_page(engine, *, fetcher: Fetcher, parser: Parser,
  url: str, entity_id: int | None, source_kind: str, render_js: bool = False) -> IngestResult`
  (frozen dataclass: `snapshot_id`, `chunks_written`, `final_url`). It fetches once, calls
  `record_snapshot`, then `parse_and_chunk(result.body_bytes, content_type=result.content_type,
  url=result.final_url, ...)` and `store_chunks(engine, snapshot_id, chunks)`. Errors: `FetchError`
  propagates with no snapshot row; `ParseError` propagates after the snapshot row exists and no
  chunk rows are written (the snapshot records a real fetch observation even when unparseable).
- Scope / non-goals: CLI wiring, crawl loop/policy (robots, rate limit), raw-byte storage
  ((D)-owed), entity table, migrations. Connections: unwired by design; the CLI `crawl`/`parse`
  stage row is its production caller. Scale: one body in memory (bounded by the fetcher's byte
  cap); chunks stream into `store_chunks` without materialising a list.
- Acceptance: `tests/test_ingest.py` (offline, in-memory SQLite, `InMemoryFetcher` + `HtmlParser`)
  written first and seen failing at base; covers happy path (row counts, heading paths, snapshot
  sha256/final_url), FetchError → no snapshot, ParseError → snapshot row and zero chunks, re-ingest →
  new snapshot id, chunks passed as a non-list iterator. `uv run mypy core` passes.
- Evidence / residuals: PR for assignment 23/A1 (branch `task/in-01-ingest-page`). Residuals: not
  wired into the CLI; not exercised against a live source (offline fakes only), so the behaviour row
  stays partial until the CLI crawl/parse run shows it; PostgreSQL path not exercised; a ParseError
  leaves a chunkless snapshot that a later parse retry must handle.

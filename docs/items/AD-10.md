# AD-10: stdlib HTML → Markdown `Parser`

Status and dependencies live in the canonical backlog (`todo.md`, Phase 0 › Adapters).

- Target references: ARCHITECTURE.md §4 (Parse & chunk: "HTML → clean Markdown (boilerplate
  removal), keep headings"); `docs/items/AD-07.md` (Parser protocol); `docs/items/AD-09.md`
  (`pages` tuple type); D-003 (neutral fixtures only).
- Objective: `HtmlParser` in `adapters/html_parser.py` converts an HTML body to Markdown with
  ATX headings (`#`..`######`), paragraphs, list items (`- `), links as `[text](href)`, and
  drops `script`, `style`, `noscript`, `template`, `nav`, `header`, `footer`, `aside` and
  `form` content. `title` comes from `<title>`; `pages=()`; `parser="html"`. It is built on
  stdlib `html.parser` only, with no new dependency.
- Semantics: bodies larger than `max_bytes` (default `5_000_000`) raise `ParseError` before
  decoding. Only `text/html` and `application/xhtml+xml` are accepted; other media types raise
  `ParseError`. Decoding uses the `charset=` parameter when present, else UTF-8, with
  `errors="replace"`; an unknown codec raises `ParseError`. Nested lists indent two spaces per
  level (ordered lists use the same `- ` marker); whitespace runs collapse to one space and
  `<br>` becomes a line break; `javascript:`, `vbscript:` and `data:` hrefs keep their text but
  are not emitted as links.
- Scope / non-goals: `adapters/html_parser.py`, `tests/test_html_parser.py`, this file. Non-goals:
  PDF/MinerU, tables-to-Markdown beyond flattening cell text, readability-style scoring, CLI
  wiring. `adapters/parser.py`, `core/`, `pyproject.toml`/`uv.lock` and `todo.md` are untouched.
- Acceptance: tests written first, failing at base `85afd07` with `ModuleNotFoundError: No module
  named 'adapters.html_parser'`. They cover headings h1-h6, nested lists, links, dropped
  boilerplate tags, whitespace collapse, `<title>`, charset decoding (latin-1), oversize body →
  `ParseError` before decode, unsupported content type → `ParseError`, empty body → empty
  Markdown, `isinstance(HtmlParser(), Parser)`, and a `parse_and_chunk` integration test whose
  chunk heading paths follow the HTML headings. Gate: `uv run pytest`; `uv run ruff check .`;
  `uv run ruff format --check core adapters tests/test_html_parser.py`; `uv run mypy core`;
  `uv run mypy --strict adapters/html_parser.py`, offline.
- Connections / scale: **unwired by design**; the CLI `parse` stage row is the production caller
  (via `core.parse_chunk.parse_and_chunk`). One body is held in memory, bounded by `max_bytes`;
  the Markdown is proportional to the decoded input.

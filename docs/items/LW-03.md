# LW-03: Attribute a lane tab whose agent pane reports a parent cwd

Status and dependencies live in the canonical backlog (`todo.md`, Phase 0 › Repo & infra).

- Target references: `.agent/supervisor.md` "Live work" (`cleanup --go` closes a lane tab only when
  its lane is finished; anything uncertain is held and reported, and tabs outside the lane paths
  are never closed); `scripts/lanes.py` module docstring (the hold reasons, `foreign` included);
  D-003 (tracked files stay domain-neutral; tests use invented lane names only).
- Objective: in `scripts/lanes.py` `cleanup`, a tab labelled with the lane prefix that has a lane
  record (by label) whose recorded `cwd` is a lane worktree path — still registered, or already
  deleted — is attributed to that worktree when its panes report cwds that are not lane paths (for
  example an `--agent` pane reporting the parent dir `/work` instead of the lane worktree). It is
  then closed as a finished lane instead of being held as `foreign`. The attribution runs after the
  `active`, `carried` and `lane <x> <state>` holds, so those still win; the `worktree-kept` hold and
  the worktree/busy rules then apply to the record's cwd exactly as if the pane had reported it. A
  labelled tab with no record, or whose panes also include a lane path, keeps today's `foreign`
  hold.
- Output: the report line is unchanged — `would close tab <id> <label>` on a dry run, `closed tab
  <id> <label>` with `--go`; every other hold prints as before.
- Scope / non-goals: `scripts/lanes.py` (`cleanup` and its module docstring), `tests/test_lanes.py`
  (the existing seam-based `CleanupTests`), this file. Non-goals: the other hold rules,
  `start`/`status`, Herdr calls, `.agent/supervisor.md` wording (not updated by this item; see
  residuals), `todo.md` (the row keeps its own status wording).
- Acceptance: `uv run pytest tests/test_lanes.py` — tests written first, failing before the change
  with `hold tab t10 live-proj-a1: foreign` for a recorded finished lane whose pane reports `/work`
  (the dry run even removed the worktree while keeping that tab). They now show (a) a `done` and a
  `recorded` record → `would close tab`, and the registered worktree `would remove`; (b) a record
  whose worktree is already gone → `would close tab` and no worktree line; (c) a `running` and a
  `blocked` record → `hold tab ...: lane a1 <state>` (attribution never bypasses `record_hold`);
  (d) a working pane → `active: working`; (e) a labelled tab with no record and pane cwd `/work` →
  still `foreign`; (f) a record whose cwd is the main checkout, not a lane worktree → still
  `foreign`; (g) a pane reporting another lane path → still `foreign`;
  (h) no listed panes for a finished record → still `foreign`. Negative controls: removing the
  attribution branch fails (a) and (b); removing the record-cwd lane check fails (f); loosening
  "panes are not lane paths" fails (g); dropping the requirement that panes are listed fails (h).
- Connections / safety: production caller is the planner's `python3 scripts/lanes.py cleanup --go`
  each round. Closing a tab needs a record by label whose cwd is a lane worktree; without one the
  tab stays `foreign`, so a tab that cannot be attributed to a finished lane is never closed. The
  record's cwd replaces the pane cwds only for the `worktree-kept`, busy and freed checks, so a dry
  run frees that worktree as a close of the tab would. Scale: one tab's panes are read per loop
  iteration; no extra process or Herdr call is added.

  c999f64. Gate offline: `uv run pytest` → 384 passed, 3 skipped (pre-existing,
  `DM_TEST_DATABASE_URL` unset), 130 subtests passed; `uv run pytest tests/test_lanes.py` → 26
  passed, 9 subtests (8 new tests, 4 new subtests); `uv run ruff check .` → passed; `uv run ruff
  format --check adapters tests` → 26 files already formatted; `uv run mypy core adapters` → no
  issues in 15 source files.
  Residuals: `.agent/supervisor.md` still says "tabs outside the lane paths are never closed"; the
  attribution makes an exception for a tab whose record names a lane worktree, and that wording is

  (only for a finished record, and only for a worktree path); no Herdr call was exercised live —
  seams only, and `cleanup --go` was never run.

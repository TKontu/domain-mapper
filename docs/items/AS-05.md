# AS-05: Wire the local verifier and routing into `landscape assess`

Status and dependencies live in the canonical backlog, not duplicated here.

- Target references: ARCHITECTURE.md §4 stage 7 (verifier after extractor; accept / adjudicate /
  silent), §6 routing (verifier is a different model family); D-003 (neutral fixtures only);
  `core/verify.py` (AS-04), `run_assess` (AS-03).
- Objective: `landscape assess` runs `verify_extraction` then `route` after `extract_criterion`
  inside the same `assess` run and prints one extra line `route KIND confidence C|- reason R`.
  The verifier model is setting `verifier_model` (`DM_VERIFIER_MODEL`, default
  `DEFAULT_VERIFIER_MODEL`), built through the test seam `_make_verify_llm(settings, db)` on the
  local gateway. Silent extractions make no verifier call (`route silent`). Verifier
  `AssessError`/`LlmError` → run failed, exit 1. Exit 0 for accept/silent, 1 for adjudicate or
  failed checks.
- Scope / non-goals: `core/cli.py` (run_assess + seam), `core/config.py` (one setting),
  `.env.example`, `tests/test_cli_assess.py`, this file, AS-04/AS-05 `todo.md` rows. No cloud
  adjudication, persistence, changes to `core/verify.py`/`core/assess.py`/`core/retrieve.py`, live
  model calls.
- Connections: production caller of `_make_verify_llm` and `verifier_model` is `landscape assess`;
  one verifier call per non-silent run.
- Acceptance: offline pytest with fake LLMs via both seams (accept, disagree → adjudicate, silent →
  no call, malformed/LlmError → failed run, seam builds with `verifier_model`), failing at base,
  passing at head.
- Evidence / residuals: PR for assignment 64/A3 (base 2dc895f). Residuals: verifier is built
  (and can fail setup, exit 2) before the run even when the extraction ends silent; verifier runs
  on the same gateway as the extractor with only the model name swapped; checks-failed extractions
  still get a verifier call though `route` adjudicates regardless; not exercised against a live
  model; adjudication itself not implemented.

# GP-01: genericity check — core carries no `_example` domain words

Status and dependencies live in the canonical backlog, not duplicated here.

- Origin: Phase 5 row "Run `scopes/_example/` end to end with zero changes to `core/` — log every
  place it was tempted" (todo.md). The offline run already exists (EX-01/02,
  `tests/test_example_m1_run.py`); what is missing is a check that the core stays domain-free and a
  log of every place it does not.
- Target references: ARCHITECTURE.md §10 (genericity contract); D-003 (public repo; examples only
  from `scopes/_example/`).
- Objective: `tests/test_core_genericity.py` collects the domain-specific identifiers and terms of
  `scopes/_example/` (vocabulary terms, segment ids, criterion/topic ids, attribute ids, profile
  ids — as loaded through `core/scope_pack.py`) and scans `core/**/*.py` source for them
  (case-insensitive, word-bounded). Every hit must appear in an allowlist
  `tests/fixtures/core_genericity_allowlist.toml` with a one-line reason; unlisted hits fail, and
  stale allowlist entries (no longer hit) also fail (ratchet). `docs/genericity-log.md` lists each
  allowlisted hit with file, term and whether it is generic (keep) or leaked (follow-up row under
  Phase 5 "Refactor any leaked domain logic").
- Acceptance: (a) test passes at the branch head and fails if a term such as an `_example` segment
  id is added to a core file (shown by a parametrized/tmp-based negative case, not by editing
  core); (b) allowlist and log agree entry for entry; (c) no changes to `core/`, `scopes/`, schema,
  ARCHITECTURE.md or decisions; (d) gate `uv run pytest -q && uv run ruff check . && uv run mypy core app` green.
- Non-goals: refactoring leaks (that is the next Phase 5 row); scanning private scopes; live runs.
- Connections / scale: no new public symbol; test + fixture + doc only; scan is bounded by core/
  source size.

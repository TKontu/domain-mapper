# AT-09: `landscape attributes-extract --all --skip-existing` skips pairs with a current value

Status and dependencies live in the canonical backlog, not duplicated here.

- Target references: ARCHITECTURE.md §4 stage 8 (quantitative attributes via structured
  extraction), §5 (`attribute_value`); AGENTS.md "Connections", "Scale"; D-003 (neutral fixtures
  only, `scopes/_example`). Follows AT-08 (`landscape attributes-extract --all`, whose residual
  was "re-runs re-extract"); uses `core.attribute_store.current_attribute_values_many` (AT-04).
- Objective: add `--skip-existing` to `landscape attributes-extract --all`. Per keyset page of
  `in_scope` entities from `core.entity_store.iter_entities`, current values are loaded once with
  `core.attribute_store.current_attribute_values_many(session, ids)` (one query per page, page
  ≤ 500) and every entity × attribute pair whose attribute id already has a current value is
  skipped. A skipped pair makes no retrieval (`search_chunks`) and no LLM call, prints
  `entity E attribute A skipped existing`, is counted in `skipped K`, does not affect the exit
  code, and leaves any stored value untouched (no new row). The batch summary becomes
  `pairs P stored S null U failed F errors X skipped K` (`pairs P` counts every entity ×
  attribute pair considered; `pairs == stored + null + failed + errors + skipped`); without the
  flag `K` is 0 and output is otherwise unchanged. `--skip-existing` is batch mode only: with
  `--entity` (single mode) it exits 2 with no run row; `--all` with `--entity` still exits 2.
  Without the flag behaviour is unchanged.
- **Stored null question (pack premise 3): nulls are not stored.** A null extraction stores no
  `attribute_value` row: `core.attribute_extract.store_attribute_extraction` writes only when
  `extraction.value` is non-null and `extraction.checks_passed` is true ("a null or failed
  extraction writes nothing"); `core.attribute_store.record_attribute_value` rejects `null`
  (`_checked_value` raises `ValueError`); `extract_attribute` with no evidence returns
  `(None, (), True, ())`. Null/failed pairs are counted (`null` / `failed`) but write nothing, so
  a pair whose last extraction was null has no current value and is NOT skipped on re-run. The
  skip test is presence-based (`attribute.id in current.get(entity.id, {})`): a pair is skipped
  iff its attribute id has a current `attribute_value` row; any stored non-null value (including
  a falsy `0`, `false`, `""`) counts; a hypothetical stored JSON null would also count, but no
  code path in this repository can create one. "Current" = latest row by `attribute_value.id`
  per (entity, attribute) (`current_attribute_values_many`).
- Scope / non-goals: batch mode only; no staleness/age-based refresh, no concurrency, no hybrid
  retrieval, no migrations, no live model calls; per-pair failure semantics unchanged; a skipped
  pair is not re-verified. Files: `core/cli.py`, `tests/test_cli_attributes_extract.py`, this
  file and the AT-09 `todo.md` row.
- **Flag lifecycle:** `--skip-existing` is a permanent batch CLI flag (default off; without it
  output is byte-identical plus ` skipped 0`). Condition that removes it: superseded by a
  staleness/age-based refresh policy or by making skipping the default in a later item; not a
  shortcut, no follow-up row required.
- Connections / scale: `_run_attributes_extract_batch` (production caller of `iter_entities`,
  `_extract_pair`) is the new production caller of `current_attribute_values_many` from the
  batch path; `current_attribute_values_many`'s other production caller remains
  `run_attributes_export`. `--skip-existing` adds exactly one query per entity page (≤ 500 ids)
  and no per-pair query; retrieval and LLM spend drop by `skipped K` pairs; memory stays bounded
  by one keyset page plus `--n` chunks per call; no change to single-entity mode. Checked, not
  assumed: callers of `run_attributes_extract` are the `attributes-extract` Typer command only;
  `_run_attributes_extract_batch` is called once; the summary line has one print site; no other
  code reads the summary string. (`scripts/system_map.py` is not present in this checkout;
  caller scan done by grep.) No new public symbol.
- Acceptance: offline pytest failing at base, passing at head (SQLite, fake LLM via monkeypatched
  `_make_assess_llm`, neutral `_example` pack + two-attribute tmp pack). Two in-scope entities,

  exactly 3 LLM calls, prints `entity E attribute A skipped existing`, summary `skipped 1`,
  `pairs 4 stored 3 null 0 failed 0 errors 0 skipped 1`, exit 0, pre-stored value unchanged (no
  new row); `--all` without the flag makes 4 calls and `skipped 0` (`pairs 4 stored 4 null 0
  failed 0 errors 0 skipped 0`); `--skip-existing --entity E` exits 2 with no run row; existing
  tests updated only for the appended ` skipped K` summary field. Page boundary (501 entities →
  pages 500 + 1, one `current_attribute_values_many` query per page) verified. Full gate green.

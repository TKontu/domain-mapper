# CH-02: parse-and-chunk stage function

Status and dependencies live in the canonical backlog (`todo.md`, Phase 1 › Parse).

- Target references: ARCHITECTURE.md §4 (Parse & chunk); D-003 (no domain words; neutral
  examples). Builds on CH-01 (`core/chunking.py`) and AD-07/AD-09 (`adapters/parser.py`).
- Objective: a pure, offline `parse_and_chunk(body: bytes, *, content_type: str, url: str,
  parser: Parser, max_tokens=600, min_tokens=300, overlap_tokens=60) -> Iterator[Chunk]` in
  `core/parse_chunk.py` that calls `parser.parse(...)` once and yields `chunk_document(...)` chunks.
- Semantics: `ParseError` propagates unchanged; invalid chunk parameters raise `ValueError` eagerly,
  before the parser is called and before iteration (validation delegated to `chunk_document`); the
  parser is called exactly once per call; an empty parsed document yields no chunks.
- Scope / non-goals: `core/parse_chunk.py`, `tests/test_parse_chunk.py`, this file, one row in
  `todo.md` Phase 1 › Parse. Non-goals: DB persistence, CLI wiring, real parsers, language
  detection, edits to `core/chunking.py` or `adapters/parser.py`.
- Acceptance: tests written first failed at base `d10f362` with
  `ModuleNotFoundError: No module named 'core.parse_chunk'`; they now show HTML-style and two-page
  `InMemoryParser` documents matching `chunk_document`, parameters forwarded, unsupported content
  type → `ParseError`, each of four invalid parameter sets → `ValueError` with a counting parser
  never called, the parser called once, and an empty document → `[]`. Negative control: removing
  the eager validation call fails the four invalid-parameter cases.
- Connections / scale: **unwired by design**; the production caller is the later Parse & chunk
  persistence row (CLI `parse` stage storing `chunk` rows). Holds one parsed document (bounded by
  parser caps) and yields chunks lazily.

  Residual: not wired into the CLI or DB.

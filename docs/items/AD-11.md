# AD-11: `HtmlParser` residual fixes from AD-10 review

Status and dependencies live in the canonical backlog (`todo.md`, Phase 0 › Adapters).

- Target references: ARCHITECTURE.md §4 (Parse & chunk: "HTML → clean Markdown (boilerplate

- Objective: in `adapters/html_parser.py` (1) a dropped tag (`header`, `nav`, etc.) left unclosed
  no longer swallows the rest of the body: dropping ends at the closing tag of an enclosing
  element or at end of `body`, so later body text still appears; (2) `pre` content keeps its
  newlines and spaces and is emitted as a fenced code block; (3) a paragraph/text line whose
  output would start with `#` is escaped (`\#`) so `chunk_document` does not read it as a heading.
- Semantics: the builder keeps an open-element stack. A dropped tag starts a drop region at its
  stack depth; the region ends when that tag or an ancestor opened before it closes, or at
  ``</body>``. ``pre`` collects raw text (``br`` becomes a newline) and emits one fenced block
  whose fence is longer than any backtick run inside it. Paragraph blocks escape a leading
  ``#`` (after at most three spaces) as ``\#``; headings, list items and code blocks keep their
  markers and are not escaped.
- Scope / non-goals: `adapters/html_parser.py`, `tests/test_html_parser.py`, this file. Non-goals:
  tables, readability scoring, PDF, CLI wiring. `todo.md`, `core/`, `adapters/parser.py` and
  `docs/items/AD-10.md` are untouched.
- Acceptance: tests written first, failing at base `e8af3e8` for each residual; they pass at head.
  All existing `tests/test_html_parser.py` tests still pass. Gate offline: `uv run pytest`;

  the open-element stack is bounded by the number of start tags, itself bounded by the input.

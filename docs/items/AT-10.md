# AT-10: `landscape attributes-export` lines carry current-value evidence

Status and dependencies live in the canonical backlog, not duplicated here.

- Target references: ARCHITECTURE.md §4 stage 8, §5 (`attribute_value`, `evidence`); AGENTS.md
  "Connections", "Scale"; D-003 (neutral fixtures, `scopes/_example` only). Follows AT-03
  (residual "no unit or evidence in the export") and AT-05 (`attribute_evidence_many`).
- Objective: each `attributes-export` JSON line gains a last key `"evidence"`: sorted attribute
  id → list of `{"chunk_id", "quote", "grounded"}` in evidence id order for the *current* value
  of that attribute (`[]` when it has none). `entity_id` and `attributes` are unchanged. Per
  ≤500-entity batch: one `core.attribute_store.current_attribute_value_rows_many` query (new;
  returns current row id + value; production caller `run_attributes_export`) and one
  `attribute_evidence_many` query (first production caller `run_attributes_export`).
  `current_attribute_values_many` keeps its signature and behaviour (now delegates).
- Scope / non-goals: export only; no schema change, migration, unit field or other command
  change; superseded values' evidence is not exported.
- Acceptance: `tests/test_cli_attributes_export.py` — current-value evidence in id order, `[]`
  for an attribute without evidence, superseded evidence absent; statement counter over 501
  entities shows 2 value and 2 evidence queries (one each per batch). Full gate green.
- Evidence / residuals: PR for assignment 85/A1; SQLite only, PostgreSQL unexercised.

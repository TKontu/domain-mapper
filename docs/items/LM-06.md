# LM-06: per-call LLM timing overlap from `llm_call`

Status and dependencies live in the canonical backlog, not duplicated here.

- Target references: ARCHITECTURE §6 local routing; RT-02 `llm_call`; CO-01 cost-report. No design change.
- Objective: `uv run python scripts/llm_timings.py DB_PATH [--run-id N] [--json]` opens a SQLite
  file read-only and prints, per purpose, calls, errors (status != ok) and p50/p95/max
  latency_ms; overall, wall span, sum of latencies and peak concurrency. Each call's interval is
  `[created_at - latency_ms, created_at]` (created_at is stamped after the call by
  `core/llm_calls.py` `log_llm_call`); touching intervals do not overlap. Percentiles are
  nearest-rank. Origin: LM-04 needs per-call timing overlap (round 147 handoff).
- Scope / non-goals: one script with an importable pure `summarise`, tests, records. Not CLI
  changes, schema changes, live runs or Postgres. Unwired by design: a planner/operator tool for
  LM-04 lane records.
- Acceptance: `tests/test_llm_timings.py` (offline): full overlap → peak 3, sequential → 1,
  touching → 1; per-purpose counts/errors/percentiles; `--run-id` filter; missing file or no
  `llm_call` table → exit 2 with one stderr line; `--json` equals `summarise`. Full local gate.
- Evidence / residuals: PR on branch task/lm-06-llm-timings. Residuals: memory O(rows) (latencies
  per purpose plus the sweep's event list); not yet run against a live lane database.

# FE-06: release labels in the mosaic

Status and dependencies live in the canonical backlog, not duplicated here.

- Target references: ARCHITECTURE.md §7 ("criteria below threshold are published as
  'experimental' or hidden"), §12 Publish; D-003 (neutral `scopes/_example`, tmp_path).
  Builds on FE-01/FE-02 (`app/mosaic.py`, `landscape mosaic`) and EV-04
  (`core.eval_thresholds.load_gate_report`, `GateReportError`).
- Objective: `landscape mosaic --gate-report FILE` marks each criterion column with its release
  label; `--hide-experimental` also omits experimental criteria from the mosaic and entity pages.
- Behaviour: with `--gate-report` every criterion `<th data-criterion>` gains
  `data-release="release|experimental|ungated"` (absent from report: `ungated`); an experimental
  header shows an escaped " (experimental)" marker; cells unchanged. With `--hide-experimental`
  experimental criteria get no header and no cells, topic `colspan` shrinks, a topic whose
  criteria are all hidden keeps its score/coverage column, and `--entity-dir` pages skip them.
  `ungated` is never hidden. Without the flags output is byte-identical to before.
  `--hide-experimental` without `--gate-report` exits 2 before reading inputs; a missing or
  malformed report exits 2 with the `GateReportError` message and writes no output.
- Scope / non-goals: `app/mosaic.py`, `app/cli.py` (`run_mosaic`, `mosaic`), tests. Non-goals:
  export/eval changes, recomputing topic scores, a publish command, live models.
- Acceptance: `tests/test_mosaic_release.py` fails at base, passes at head; local gate green.
- Residuals: topic score/coverage values are shown as exported and include hidden criteria;
  seen only on fixtures.

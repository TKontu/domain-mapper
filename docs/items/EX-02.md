Status and dependencies live in the canonical backlog, not duplicated here.

- Target references: ARCHITECTURE.md §5 (data model: snapshot, chunk, evidence,
  market_presence); D-003 (neutral fixtures only, `scopes/_example`, invented names);

- Objective: `scripts/example_m1_run.py` uses real stored evidence instead of synthetic chunk
  ids. Per entity it seeds one snapshot (`core.snapshot_store.record_snapshot`, url
  `https://<name>.example/about`, fixed `fetched_at`) and neutral chunks
  (`core.chunk_store.store_chunks`); chunk text carries the `_example` `presence_terms`
  (Avalor/Brennmark/Calvessa) only for the entities meant to have those presences. Assessment
  quotes cite those chunk ids and appear verbatim in the chunk text. Presences the terms can find
  are recorded by `landscape presence-extract --scope ... --type <type> --entity <id>` CLI steps;
  the rest (XZ remote, delta's XA field_service) stay `presence-set`. Epsilon keeps no presence.
  The summary JSON gains the summed `extracted` count.
- Scope / non-goals: the script, `tests/test_example_m1_run.py`, `docs/runs/EX-02.md`. No
  core/app behavior change, no scope pack change, no LLM, no network, no Postgres, no browser,
  no scaling to ~20 entities.
- Acceptance: the test (failing at base: evidence url empty, no presence-extract step) asserts
  every step exits 0; a presence-extract step exists and `extracted` >= 3; each extracted
  presence row's `evidence_id` is a chunk of that entity whose text contains the term and whose
  snapshot url is `https://<name>.example/...`; every assessment evidence quote is verbatim in a
  chunk of its entity; EX-01 assertions kept (`--layer` rows exact, epsilon only unfiltered);
  every entity page's evidence list is nonempty and shows an `https://<name>.example/` url and a
  `fetched` timestamp. Full gate green. Run record: `docs/runs/EX-02.md`.
- Residuals: snapshots/chunks are seeded through store APIs, not crawled or parsed; segments and
  assessments are still seeded (no LLM); 5 entities, SQLite, no browser run; `presence-extract`
  takes one `--type` per call, so the script runs one call per type with `--entity`.

# AT-06: attribute extraction with grounded evidence

Status and dependencies live in the canonical backlog, not duplicated here.

- Target references: ARCHITECTURE.md §4 stage 8 (content attributes via structured extraction +
  the same verification pattern as assessments), §5 (`attribute_value`, `evidence`), §6 LLM
  routing (attribute extraction: local extractor, cloud verifier); AGENTS.md "Connections",
  "Scale"; D-003 (neutral fixtures only, `scopes/_example`).
- Objective: new `core/attribute_extract.py`, mirroring `core/assess.py`.
  `extract_attribute(llm, attribute, chunks, *, run_id, max_chars=12000) -> AttributeExtraction`
  asks the model through the `adapters.llm.LLM` protocol (purpose `"attribute_extract"`) with a
  JSON schema built from the attribute type: the value is typed per `Attribute.type`, an enum is
  limited to `Attribute.values`, and every type is nullable for "not stated"; quotes may cite
  only the given chunk ids. Deterministic checks: the value is validated with the same rules as
  `core.attribute_store._checked_value` (reused, not duplicated); every quote is grounded with
  `core.grounding.ground_and_locate` at tier 1/2 exactly as assess does; a non-null value needs
  at least one grounded quote or `checks_passed` is False with a named failure. Malformed output
  raises a named error whose message names the field only. No chunks returns a null value without
  an LLM call. `store_attribute_extraction(session, entity_id, attribute, extraction, *,
  run_id=None) -> int | None` writes through `record_attribute_value(...,
  evidence=[(chunk_id, quote, grounded), ...])` only when the value is non-null and the checks
  passed, returning the value id or None; the caller owns the transaction.
- Scope / non-goals: extraction, checks, store helper and tests only. No CLI, retrieval, export,
  migration or live model calls; existing assess and attribute behaviour unchanged. Files:
  `core/attribute_extract.py`, `tests/test_attribute_extract.py`, this file and the AT-06
  `todo.md` row.
- Connections / scale: `extract_attribute` and `store_attribute_extraction` are the first
  production callers of `record_attribute_value(evidence=)`; they are themselves unwired by
  design until a later `landscape attributes-extract` CLI row (residual). Input is bounded by
  `max_chars`; one LLM call per entity × attribute.
- Acceptance: offline pytest failing at base, passing at head — an int value with a grounded
  quote stores one value and one evidence row (`attribute_value_id` set); an enum value outside
  `values` raises/fails without writes; an ungrounded quote gives `checks_passed` False and the
  store writes nothing; a null value writes nothing; empty chunks makes no LLM call; a quote
  citing a non-given chunk id raises; the prompt neutralises delimiters for a chunk containing
  `<<<END EVIDENCE>>>`. Full gate green.
- Evidence / residuals: assignment 81/A1; the PR body carries the head SHA and gate counts.
  Residuals: SQLite only, PostgreSQL unexercised; no live model call (tests use a fake `LLM`);
  unwired until the `landscape attributes-extract` CLI row.

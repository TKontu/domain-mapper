# AG-02: scores CLI

Status and dependencies live in the canonical backlog, not duplicated here.

- Target references: ARCHITECTURE.md §10 Aggregate & score; AG-01 (`core/aggregate.py`
  `score_topics`); `core/screen_store.py` (`ScreenResultRow.segments`, `created_at`);
  `core/assessment_store.py` (`iter_current_assessments`); D-003 (neutral fixtures only,
  `scopes/_example/`).
- Objective: CLI `landscape scores --scope S --entity ID [--segment SEG ...]` prints per-topic
  score and coverage for one entity.
  - New read-only `latest_screen_segments(engine, entity_id) -> tuple[str, ...] | None` in
    `core/screen_store.py`: segments of the entity's latest `screen_result` row (highest
    `created_at`, ties by highest `id`); `None` when the entity has no screen result.
  - New `run_scores(scope, entity_id, segments)` in `core/cli.py` plus the `scores` typer
    command: load the pack (`_load`); entity segments = `--segment` values when given (each must
    be a scope segment id, else exit 2 naming it), else `latest_screen_segments`; none → exit 2
    `error: entity N has no screen result; pass --segment`. Assessments =
    `iter_current_assessments(engine, entity_id=ID, rubric_version=pack.scope.version)` (the
    version `landscape assess` stores) passed straight to `score_topics`. Output: first line
    `entity ID segments a,b rubric V`, then one line per topic in rubric order
    `topic T score X.XXXX|- coverage X.XXXX|- applicable A scored S evidenced E` (4 decimals,
    `-` for None). A `ValueError` from `score_topics` exits 1 with `error: <msg>`;
    `SQLAlchemyError` goes through `_exit_database_unavailable` (exit 2, one line).
- Scope / non-goals: `core/cli.py`, `core/screen_store.py`, `tests/test_cli_scores.py`,
  `tests/test_screen_store.py` (reader tests), this file and the AG-01/AG-02 `todo.md` rows. No
  schema change, profiles/weights, silent penalty, multi-entity tables or export changes.
- Acceptance: offline pytest failing at base and passing at head — reader returns latest
  segments, tie by id, `None` for no row; CLI prints header plus rubric-ordered topic lines with
  correct numbers for a seeded entity (stored screen segments); `--segment` overrides the stored
  result; unknown `--segment` exits 2; no screen result and no `--segment` exits 2; assessments
  of another rubric version are ignored; entity with no assessments prints `-` scores and
  `0.0000`/`-` coverage per AG-01 rules; database unavailable exits 2 with one line. Full gate
  green.
- Connections / scale: `run_scores` is the production caller of `score_topics` and
  `latest_screen_segments`; the `scores` command calls `run_scores`. One entity per call; the
  assessment iterator is consumed once (memory bounded by rubric size plus one batch).

  and profile weights not implemented; seen offline only.

# AG-05: batched scores export queries

Status and dependencies live in the canonical backlog, not duplicated here.

- Target references: ARCHITECTURE.md §5 (`screen_result`, `assessment`), §6 exports; AGENTS.md
  "Scale" and "Connections"; `core/screen_store.py` (`latest_screen_segments`, SC-02);
  `core/assessment_store.py` (`iter_current_assessments`, AS-11); `core/cli.py`
  (`run_scores_export`, AG-04); AT-04 (`run_attributes_export` batching precedent); D-003
  (neutral fixtures only, `scopes/_example`).
- Objective: `landscape scores-export` issues a bounded number of queries per batch of at most
  500 entities (`SCORES_EXPORT_BATCH = 500` in `core/cli.py`) instead of per entity, with
  byte-identical output. Add
  `latest_screen_segments_many(engine, entity_ids) -> dict[int, tuple[str, ...]]` to
  `core/screen_store.py`: one query for the ids; per entity with a screen result, the segments of
  its latest one (highest `created_at`, ties highest `id`, same rule as
  `latest_screen_segments`); entities without one absent; empty input returns `{}` without
  querying. Add an `entity_ids: Sequence[int] | None = None` filter to `iter_current_assessments`
  in `core/assessment_store.py`, applied before ranking like the other filters (an empty sequence
  yields nothing without querying); existing callers unchanged. `run_scores_export` collects
  entities from `iter_entities` in batches of ≤`SCORES_EXPORT_BATCH`; per batch it calls
  `latest_screen_segments_many` once and `iter_current_assessments(entity_ids=batch_ids,
  rubric_version=version)` once, groups assessments by entity id, and scores/writes in ascending
  entity id. Skip counting, `.tmp` + `os.replace` atomic write, exit codes (2 setup/unwritable,
  1 on a `score_topics` `ValueError` naming the entity) and output bytes stay identical to AG-04.
- Scope / non-goals: scores-export only; `latest_screen_segments` and `run_scores` unchanged. No
  schema change, no scoring change (silent penalty / profile weights stay out). No change to
  `landscape export` or `landscape attributes-export`. Files: `core/screen_store.py`,
  `core/assessment_store.py`, `core/cli.py`, `tests/test_screen_store.py`,
  `tests/test_assessment_store.py`, `tests/test_cli_scores_export.py`, this file and the AG-05
  `todo.md` row.
- Connections / scale: production caller of `latest_screen_segments_many` and of the
  `entity_ids` filter is `run_scores_export`; memory bounded to one batch (≤500 entities'
  segments and current assessments with evidence); `IN` lists ≤500 ids; read-only.
- Acceptance: offline pytest failing at base, passing at head — over three entities (one with
  two screen results, one with one, one without) the batched call returns the latest segments for
  the two, matching `latest_screen_segments`, and omits the third; empty input → `{}` with no
  statement executed; `iter_current_assessments(entity_ids=[...])` returns exactly the subset of
  the unfiltered view for those ids, and an empty sequence yields nothing; an export with
  batch size 2 over 5 entities (one unscreened) yields the same lines as batch 500 and calls
  `latest_screen_segments_many` once per batch. Existing AG-04 export tests pass unchanged. Full
  gate green.
- Evidence / residuals: assignment 79/A1; the PR body carries the head SHA and gate counts.
  Residuals: SQLite only, the PostgreSQL path is unexercised; silent penalty and profile weights
  are still not implemented.

# FE-04: mosaic --layer filter and layers in scores-export

Status and dependencies live in the canonical backlog, not duplicated here.

- Target references: ARCHITECTURE.md frontend row (static site, no backend) and Layer row
  (membership derived from market presence); D-003 (neutral fixtures only, `scopes/_example`);
  GV-01/GV-02/GV-03 ratchets; round 106 decision (Python-rendered static HTML, no JS toolchain);
  M1 "one layer of one scope". Builds on FE-03 and MP-01.
- Objective: `landscape scores-export` adds a `layers` key to every line: scope layer ids (scope
  order) from `core.presence_store.layer_ids_for` over the entity's presence countries, fetched
  with one `presences_many` call per existing ≤500-id batch; no presence gives `[]`.
  `scores --format json` is unchanged. `landscape mosaic ... --layer ID` (optional, repeatable)
  keeps only scores lines whose `layers` contains one of the ids (union, input order) via
  `app/mosaic.py::filter_by_layers` (pure, streaming); a line without `layers` is dropped. With
  `--segment` both filters apply (intersection); with `--entity-dir` pages only for kept
  entities. The heading names the layer filter (escaped) alongside any segment filter. An id not
  in the scope's `layers` exits 2 naming it and writes nothing. Without the flag, output is
  byte-identical to FE-03.
- Scope / non-goals: `app/cli.py` (`run_scores_export`, `run_mosaic`/`mosaic`), `app/mosaic.py`.
  Non-goals: presence extraction, weighting presence types, JS, maps, network, Postgres runs,
  migrations, `scores` output changes, profile weights.
- Acceptance: offline pytest (`tests/test_mosaic_layer.py`) failing at base, passing at head:
  layers derived from recorded presences and fetched once per batch; filter order and union;
  intersection with `--segment`; entity pages only for kept entities; unknown id exits 2, no
  files written; no-flag output unchanged; heading escaped. Full gate green, both ratchets pass.
- Evidence / residuals: round 110/A1 PR (see todo.md); SQLite only; no browser or real-export
  run; manual presence only; scope layers carry no `label`, so the heading shows the layer id.
